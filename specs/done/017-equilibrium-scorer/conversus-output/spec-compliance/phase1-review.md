## Functional Requirements

### FR-001: Plugin registration as `equilibrium-scorer` with hooks `[POST_PHASE_5, POST_DELIBERATION]`

**MET**

`EquilibriumScorer.name = "equilibrium-scorer"` and `EquilibriumScorer.hooks = [HookPoint.POST_PHASE_5, HookPoint.POST_DELIBERATION]`. Tests in `TestPluginRegistration` verify this. The plugin subclasses `Plugin` ABC.

### FR-002: Part of `conversus-nashopt` package

**MET**

The plugin lives at `conversus/plugins/nashopt/scorer.py` and is exported from `conversus.plugins.nashopt.__init__`. The `__all__` list includes `EquilibriumScorer`. Tests verify importability.

### FR-003: Extract features using `conversus-features` API

**MET**

`_try_extract_features(state)` calls `extract_features(output_dir, state.mode)` from `conversus.schemas.extraction`. Falls back to `_round_features_from_state(state)` if extraction fails.

### FR-004: Construct per-agent payoff functions based on deliberation mode

**MET**

`payoffs.py` implements mode-specific payoff functions: `cooperative_payoff`, `winner_take_all_payoff`, `prisoners_dilemma_payoff`, `red_blue_payoff`. The `compute_payoff` dispatcher selects by mode string. All four modes from Section 2 are covered.

### FR-005: Use nashopt's `check_equilibrium()`

**NOT MET**

The code imports `nashopt` and sets `_NASHOPT_AVAILABLE = True` if successful, but never actually calls `nashopt.check_equilibrium()`. The heuristic payoff functions are always used regardless of nashopt availability. The `solver` field in output reports "nashopt" when the package is installed, which is misleading since the heuristic is always used.

Evidence: `_compute_equilibrium_score()` (lines 121-190 of scorer.py) always calls `compute_payoff()` from payoffs.py. No call to any nashopt API exists in the codebase.

### FR-006: Equilibrium quality score as `agents_at_equilibrium / total_agents` in [0.0, 1.0]

**MET**

Line 181: `score = agents_at_eq / total_agents`. Tests verify the range and the formula.

### FR-007: Output structure with required fields

**PARTIALLY MET**

All required fields are present: `score`, `agents_at_equilibrium`, `total_agents`, `per_agent`, `mode`, `round`, `hook`. However, the `hook` field is set to `"equilibrium-scorer"` (the plugin name) instead of the actual hook name (e.g., `"post_phase_5"` or `"post_deliberation"`). The wrapping `execute_hooks()` function does write the correct hook to the output JSON file, but the PluginResult.data itself has the wrong value.

### FR-008: POST_PHASE_5 filename includes round number

**PARTIALLY MET**

The output filename is `equilibrium-scorer-post_phase_5-round-{N}.json`, which does include the round number. However, the spec says the filename MUST be `equilibrium-score-round-{N}.json`. The actual name includes the hook name and uses the plugin name stem. This is generated by `execute_hooks()` in base.py, not the scorer itself, and is consistent across all plugins. The intent (round-specific files) is met but the exact format differs.

### FR-009: Plain-language recommendation

**MET**

`_build_recommendation()` generates strings matching the spec's format: "Equilibrium quality: {score} -- {count} of {total} agents are at best response." Agents not at equilibrium are listed by name. The spec mentions identifying specific recommendations (e.g., "recommendation #3") which is not implemented, but the agent-level identification is present.

### FR-010: Config threshold with default 0.85

**MET**

`threshold = config.get("threshold", 0.85)`. Default is 0.85. Tests verify both default and custom thresholds.

### FR-011: Below-threshold recommendation

**MET**

When `score < threshold`, the recommendation includes: "Score {score} is below threshold {threshold}. Consider another round or arbitration to improve equilibrium quality." Exact wording matches spec intent.

### FR-012: Feature extraction failure handling

**MET**

Returns `PluginResult(data={"error": "..."}, advisory=True)` on unknown mode. Falls back to state-based features on extraction failure. Tests verify both paths.

### FR-013: Solver failure handling

**MET**

Try/except wraps `_compute_equilibrium_score()`. Returns partial result with error data on failure. Per-agent failures are also caught. Tests verify error handling.

## Success Criteria

### SC-001: All agents at equilibrium yields score 1.0

**MET**

`TestScoreNormalization.test_all_at_equilibrium_score_1` -- both agents have equal surviving_count (3), both at best response, score = 1.0.

### SC-002: Agent could have done better yields score < 1.0 with identification

**MET**

`TestScoreNormalization.test_partial_equilibrium_score` -- agent-a has 4 surviving, agent-b has 2. Score = 0.5 (1 of 2 at equilibrium). The `per_agent` dict identifies which agent is not at equilibrium.

### SC-003: Meaningful differentiation between converged and disputed outcomes

**MET**

The scorer produces 1.0 for fully converged (equal surviving counts) and 0.5 for disputed (unequal counts). The multi-mode integration tests show valid scores across all modes.

### SC-004: `pip install conversus-nashopt` installs dependencies

**NOT VERIFIED**

No packaging configuration (setup.py, pyproject.toml for the nashopt package) was provided for review. The code lives within the conversus package tree, not as a separate installable package. This SC cannot be verified from the code alone.

### SC-005: Core output unmodified, `plugins/equilibrium-score.json` added

**MET**

The plugin writes only to `plugins/` namespace via `execute_hooks()`. The `advisory=True` flag ensures no core modification. Tests verify output file existence in the correct directory.

### Dangerous Contradictions

- **Transition criteria priority classification**
  - **scope-boundary claims**: Transition criteria are the "most important recommendation" (Executive Summary) and should be added at P1 priority (Actionable Recommendations, Rec 1: "Priority: P1"). scope-boundary frames this as a Phase 2 binding output that "Phase 3 was obligated to implement" (Missed Opportunities, bullet 1) and assigns impact: **high**.
  - **compliance claims**: Transition criteria are absent and represent a "Phase 3 compliance gap" (Missed Opportunities, bullet 6) but are rated impact: **medium** and assigned P2 priority (Actionable Recommendations, Rec 4: "Priority: P2"). My review treats this as a should-fix rather than a must-fix, reasoning that the Phase 2 synthesis placed the criteria as a "P2 — Should implement" item (final.md L202-203).
  - **Why this is dangerous**: If both priority assignments are sent to the implementor without resolution, the implementor receives conflicting signals about whether transition criteria block the Phase 3 checkpoint. If the implementor follows scope-boundary's P1 (blocking), they must add transition criteria before the checkpoint can pass. If they follow compliance's P2 (non-blocking), they may proceed without them. The failure mode is a checkpoint that passes under one review's criteria but fails under the other's, making the gate outcome ambiguous.
  - **Suggested resolution**: The Phase 2 synthesis (final.md L171) explicitly calls this a "binding commitment" for T008, but classifies it as P2 in the Actionable Spec Changes (final.md L202). The binding language is stronger than the priority label. I should yield upward to P1, since the synthesis's use of "binding commitment" was meant to prevent exactly the scenario where this is treated as optional. scope-boundary's reading of the synthesis is more faithful on this point.

- **FR-017 effort field completeness — primary concern vs. secondary concern**
  - **scope-boundary claims**: FR-017 effort field incompleteness is not listed in the Missed Opportunities or Actionable Recommendations. scope-boundary's review does not flag the absence of the four-dimension breakdown (new files, logic complexity, testing surface, relative effort) as a compliance gap. The Effort fields are not mentioned in scope-boundary's Alignment section either, suggesting they were assessed as satisfactory or out of scope.
  - **compliance claims**: FR-017 effort field incompleteness is my "most important recommendation" (Executive Summary) and the highest-priority actionable item (Actionable Recommendations, Rec 1: "Priority: P1"). I cite FR-017's "covering" language (spec.md L242) as requiring all four dimensions, not just the relative effort label.
  - **Why this is dangerous**: If scope-boundary's implicit acceptance of the current Effort fields is adopted, the four-dimension breakdown is never added, and FR-017 is treated as satisfied by summary-level effort descriptions. If compliance's P1 is adopted, all five spec entries must be enriched before the checkpoint passes. An implementor following scope-boundary's review would ship the current Effort fields; an implementor following compliance's review would not. The documents that result are materially different in information density for the Effort fields.
  - **Suggested resolution**: The spec text (spec.md L242) is unambiguous: "covering: new files, logic complexity, testing surface, and relative effort." The colon-and-list construction is enumerative, not illustrative. scope-boundary's review may have deprioritized this because it falls outside scope-boundary's core mandate (scope violations, taxonomy drift, forward references). compliance should hold this position, and scope-boundary should acknowledge that the current Effort fields are incomplete against the FR's literal requirements.

- **Phase 2 residuals — flag-only vs. fix-now**
  - **scope-boundary claims**: The spec 003 "Not started" label (Missed Opportunities, bullet 4) and compound-label rule (Missed Opportunities, bullet 5) are explicitly characterized as "Phase 2 scope" issues. scope-boundary states "I note this as a pre-existing gap that Phase 3 inherited" and recommends fixing spec 003's label at P1 (Rec 2) and verifying the compound-label rule at P2 (Rec 5) but frames these as Phase 2 residuals rather than Phase 3 obligations.
  - **compliance claims**: The same issues are flagged as compliance gaps in my review (Missed Opportunities, bullets 5 and 6) but I also classify the "Not assessed" label as P1 (Rec 2) and the compound-label rule as P1 (Rec 3). However, I frame the compound-label rule as P1 because "Phase 2 synthesis P1-4 (final.md L192) recommended this as a P1 change," treating Phase 2 residuals as obligations Phase 3 inherited, not just pre-existing context.
  - **Why this is dangerous**: The contradiction is about ownership, not substance. Both reviews agree the fixes are needed. But scope-boundary's "inherited from Phase 2" framing could allow Phase 3 to pass its checkpoint while claiming these are out-of-scope Phase 2 failures. compliance's framing treats them as Phase 3 blockers. If the synthesis adopts scope-boundary's ownership model, the compound-label rule might never be implemented because no phase claims responsibility. If it adopts compliance's model, Phase 3's scope expands beyond its task list.
  - **Suggested resolution**: Pragmatically, these fixes should happen now regardless of which phase "owns" them, because STATUS.md cannot be a "complete cross-spec reference" (the Phase 3 checkpoint) if it contains undefined labels. Both reviews agree on this. The synthesis should adopt the pragmatic position: fix them in Phase 3, attribute the obligation to Phase 2, and note the Phase 2 implementation gap for process improvement. Neither agent needs to yield on substance; only the attribution framing needs to be harmonized.

### Tensions

- **Scope of maintenance note — narrow vs. broad**
  - **scope-boundary's position**: The maintenance note (STATUS.md L138) is too narrow because it only covers "implementation or acceptance status changes" but Phase 3 added living-content sections (Shared Subsystems, Structure Plan) not covered by the trigger (Missed Opportunities, bullet 6; Off-Base Assumptions, bullet 2). scope-boundary recommends broadening the note to include subsystem stability changes, consumer changes, and Structure Plan updates (Rec 6, P3).
  - **compliance's position**: The maintenance note's FR-008a sub-identifier is the problem, not the scope of the trigger. My review (Missed Opportunities, bullet 4) flags the "(FR-008a)" reference as untraceable to the spec's FR list and recommends normalizing it to "(FR-008)" (Rec 7, P3). I do not address the trigger's content scope.
  - **Nature of tension**: These positions address different aspects of the same maintenance note. scope-boundary wants to expand what triggers updates; compliance wants to fix the FR citation. Both can coexist, but they pull in different directions on what the maintenance note's primary deficiency is. If only one is implemented, the other gap persists.
  - **Coordination needed**: The synthesis should combine both: normalize the FR reference to "(FR-008)" and broaden the trigger language per scope-boundary's formulation. These are independent changes to the same line and can be merged into a single edit.

- **Spec 005 in SKILL.md Structure Plan — missing vs. out-of-scope**
  - **scope-boundary's position**: The SKILL.md Structure Plan (STATUS.md L66-84) should include a spec 005 entry because spec 005 has more pending SKILL.md work than any other spec (Missed Opportunities, bullet 7; Rec 7, P3). scope-boundary acknowledges T012 only names specs 002, 003, 004 but argues FR-019 says "future spec implementations" without limiting to those three.
  - **compliance's position**: My review (Alignment, bullet 5) notes that "entries for all three specs exist" and marks T012 as satisfied. I do not flag the absence of spec 005 from the Structure Plan because T012 (tasks.md L67) explicitly names "specs 002, 003, 004" and the implementation matches the task specification.
  - **Nature of tension**: scope-boundary reads FR-019 broadly ("future spec implementations" = all specs with pending work); compliance reads T012 literally (the task says three specs, three specs are present). This is a task-fidelity-vs-FR-fidelity tension — T012's paraphrase of FR-019 narrowed the scope, and the two reviews disagree about which authority controls. The tension mirrors my Off-Base Assumptions finding about T011 paraphrasing FR-017.
  - **Coordination needed**: The synthesis should note that T012 is task-compliant but FR-019-incomplete. If the checkpoint is evaluated against tasks, T012 passes. If evaluated against FRs, it needs a spec 005 entry. The synthesis should recommend the spec 005 entry as a low-cost addition (scope-boundary's Rec 7, P3) that closes the gap between task and FR without reopening T012's scope.

- **Spec 005 gap list completeness — verified vs. unverified**
  - **scope-boundary's position**: scope-boundary does not question the accuracy of spec 005's gap list (STATUS.md L60: FR-007, FR-011, FR-014, FR-015). The spec 005 self-entry is marked as clean in scope-boundary's Alignment section (bullet 5): "The entry describes spec 005's own state without creating a recursive dependency."
  - **compliance's position**: My review (Rec 9, P3) questions whether the four listed gaps accurately represent all unimplemented FRs, noting that tasks.md shows 8 remaining FRs at Phase 3 entry and the gap list appears to represent only SKILL.md-targeted FRs. I recommend verification.
  - **Nature of tension**: scope-boundary assessed the self-entry structurally (does it avoid circularity? does it contain the required fields?). compliance assessed it substantively (are the gap values accurate?). Both assessments are valid but operate at different levels of scrutiny. A structurally sound entry with an inaccurate gap list still fails SC-003's "zero ambiguity" criterion.
  - **Coordination needed**: The synthesis should note that scope-boundary's structural assessment and compliance's substantive assessment are complementary, not competing. The gap list should be verified for completeness — this is a low-effort check that strengthens both agents' positions.

- **Impact severity calibration**
  - **scope-boundary's position**: The transition criteria absence is rated "impact: **high**" (Missed Opportunities, bullet 1). The maintenance note narrowness is "impact: **low**" (Missed Opportunities, bullet 6). The missing "Depends On" fields for specs 001 and 004 are "impact: **medium**" and "impact: **low**" respectively (Missed Opportunities, bullets 2 and 3).
  - **compliance's position**: The FR-017 effort breakdown absence is my highest impact item (implicitly high, given P1 priority). The transition criteria absence is "impact: **medium**" (Missed Opportunities, bullet 6). The "Depends On" field for spec 001 is "impact: **low**" (Missed Opportunities, bullet 3).
  - **Nature of tension**: The two reviews use impact ratings that do not align. scope-boundary's highest-impact item (transition criteria) is compliance's medium-impact item. compliance's highest-impact item (FR-017 effort breakdown) does not appear in scope-boundary's review at all. An implementor reading both reviews cannot determine a unified priority ordering.
  - **Coordination needed**: The synthesis must establish a single priority ordering that integrates both perspectives. The most productive approach: accept that scope-boundary and compliance are measuring different kinds of impact (scope-boundary measures scope/boundary integrity; compliance measures FR satisfaction fidelity) and present both dimensions in the unified recommendation.

### Safe Agreements

- **Spec 003 acceptance label must change from "Not started" to "Not assessed"**
  - **Shared position**: Both reviews identify STATUS.md L45 (`**Acceptance**: Not started`) as using a label not defined in the Acceptance Tier taxonomy. scope-boundary (Missed Opportunities, bullet 4; Rec 2 and Rec 8, both P1) and compliance (Missed Opportunities, bullet 5; Rec 2, P1) both recommend adding "Not assessed" to the taxonomy and applying it to spec 003. Both cite Phase 2 unanimous convergence (final.md L122-126) and FR-009 (spec.md L216).
  - **Combined evidence**: scope-boundary provides the additional observation that "Not started" is defined in the Implementation Tier (L13) but not the Acceptance Tier, making this a "cross-tier label reuse" that the Phase 2 deliberation identified as an orthogonality violation. compliance provides the additional observation that this directly contradicts SC-005's "zero labeling disagreements" criterion. Together, the evidence establishes three independent grounds for the fix: FR-009 violation, Phase 2 binding convergence, and SC-005 failure.
  - **Confidence level**: High. Both reviews assign P1 priority. Phase 2's unanimous convergence on this point (final.md L122-126) leaves no room for deferral. This should be treated as a blocking item.

- **"Depends On" field should be present for spec 001**
  - **Shared position**: Both reviews note that spec 001 (STATUS.md L30-35) lacks a "Depends On" field despite the Cross-Spec Dependencies section (L111) showing it has no dependencies. scope-boundary (Missed Opportunities, bullet 2; Rec 3, P2) and compliance (Missed Opportunities, bullet 3; Rec 5, P2) both recommend adding `**Depends On**: None (foundational)` or equivalent. Both cite STATUS.md L129's note that "per-spec entries are authoritative."
  - **Combined evidence**: scope-boundary adds the observation that spec 004 also lacks the field (Rec 4, P2), creating a pattern of two specs with missing dependency fields. compliance focuses on the ambiguity: "a reader cannot determine whether the dependency was assessed or simply omitted." Together, the evidence shows both a consistency gap (two specs missing the field) and an interpretive ambiguity (assessed vs. omitted), reinforcing the need for the fix even though neither review rates it higher than P2.
  - **Confidence level**: Medium. Both reviews agree on substance and priority (P2). The fix is low-cost and eliminates ambiguity, but it is not blocking. The consistency argument from scope-boundary (covering spec 004 as well) strengthens the case for doing both specs together.

- **Phase 2 binding commitments create Phase 3 obligations**
  - **Shared position**: Both reviews treat the Phase 2 synthesis's "binding commitment" language (final.md L171, L202) as creating enforceable obligations for Phase 3 implementation. scope-boundary (Missed Opportunities, bullet 1): "This is a Phase 2 binding output that Phase 3 was obligated to implement." compliance (Off-Base Assumptions, bullet 2): "If Phase 2's synthesis is authoritative, these are outstanding obligations that Phase 3 inherited."
  - **Combined evidence**: scope-boundary provides the specific citation (final.md L202) and the exact formulation that was agreed. compliance provides the broader observation that multiple Phase 2 P1 changes (compound-label rule, transition criteria, "Not assessed" label) were not implemented in Phase 2 and not addressed in Phase 3's task list. Together, the evidence establishes that the Phase 2 synthesis created a set of obligations that were neither completed in Phase 2 nor explicitly assigned to Phase 3, creating an obligation gap that both reviews independently identified.
  - **Confidence level**: High. The agreement here is about process integrity, not just a single fix. If Phase 2 binding commitments are not enforceable, the deliberation process loses its ability to produce durable agreements. Both reviews converge on this principle, which should inform how the synthesis treats all Phase 2 residuals — not just transition criteria.

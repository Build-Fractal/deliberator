### Dangerous Contradictions

- **Criterion 3 self-assessment: valid compliance vs. category error**
  - **gate-skeptic claims**: "The SIR answers a question about the body content's distinctness from peer principles, which has been true since v2.3.2, as if it were a question about the rewrite's distinctness, which is a category error. Criterion 3 was designed to block duplicate principles; it has no defined behavior when applied to a within-principle structural reorganization." (Off-Base Assumptions, second item)
  - **cross-principle-coherence claims**: "The SIR includes explicit Criterion 1/2/3 self-assessments with concrete mechanical-check sketches for each structural requirement… Each check is 'concrete enough that an engineer reading the principle can sketch the check in one paragraph,' satisfying the gate's stated standard (Governance, Constitutional Inclusion Criteria, Criterion 1)." (Alignment, fourth bullet)
  - **Why this is dangerous**: These positions are directly incompatible on a question that determines whether the amendment is gate-compliant at all. If gate-skeptic is correct that the Criterion 3 self-assessment is methodologically invalid, then the amendment's gate compliance is unresolved even after all of gate-skeptic's other fixes are applied — none of gate-skeptic's seven recommendations addresses the Criterion 3 methodology problem. If cross-principle-coherence is correct that the self-assessment is substantive, then no Criterion 3 fix is needed and gate-skeptic's off-base assumption analysis overstates the problem. Synthesis cannot treat both positions as simultaneously valid: an amendment cannot be both gate-compliant and structurally non-compliant with Criterion 3 at the same time.
  - **Suggested resolution**: gate-skeptic's diagnosis is structurally correct — Criterion 3 was designed to prevent duplicate principles, not to audit within-principle reorganizations, so applying it to this rewrite answers the wrong question. However, cross-principle-coherence's conclusion (the self-assessment is substantive) is also defensible if Criterion 3 is interpreted as asking "does the elevated body content cover distinct ground?" rather than "does the reorganization itself add distinct content?" The cooperative resolution is gate-skeptic's Recommendation 7 (disclose the gate-scope question in the SIR) combined with cross-principle-coherence's Recommendation 2 (add explicit governance text defining headline rewrites as wording-level amendments). This makes the interpretive choice explicit rather than leaving it as silent precedent. cross-principle-coherence should yield on the claim that the existing self-assessment "satisfies the gate's stated standard" without qualification; gate-skeptic should acknowledge the interpretation is defensible rather than simply invalid.

- **XVI's authority to impose a constitutional MUST on plugin output format**
  - **gate-skeptic claims**: "XVI's plain-language output pairing requirement targets plugin *output format* — what plugins must include in their recommendations. It does not modify the extension mechanism itself… This is consistent with XV's registry-as-extension-interface clarification, which reserves the registry as the only sanctioned extension point; XVI adds a constraint on output content, not on extension plumbing." (Alignment, last bullet)
  - **cross-principle-coherence claims**: "XVI has unilateral jurisdiction to MUST-require plugin output format" is an off-base assumption because "XV governs what plugins can and cannot do with their output, including the warn-and-continue enforcement model… The MUST is orphaned from the enforcement mechanism that would give it operational meaning." (Off-Base Assumptions, second item)
  - **Why this is dangerous**: gate-skeptic treats XVI's plugin output MUST as constitutionally legitimate and proposes to strengthen its mechanical language (Recommendation 1: "every numerical recommendation field in plugin output has an adjacent string-typed explanation field"). If cross-principle-coherence is correct that XVI lacks unilateral jurisdiction, gate-skeptic's Recommendation 1 makes the jurisdictional problem worse by encoding a stronger, more mechanically precise MUST in XVI without any coordination with XV's enforcement machinery. The failure mode is concrete: a future implementor reads XVI's strengthened mechanical MUST, concludes it requires schema-level rejection of non-compliant plugin output, and triggers a core execution block — a direct XV violation — while citing XVI as authority. Both reviews identify this as a foreseeable failure mode; they disagree on whether XVI's current framing already creates it.
  - **Suggested resolution**: cross-principle-coherence's Recommendation 1 (add explicit warn-and-continue carve-out citing XV) and cross-principle-coherence's Recommendation 5 (cross-reference XV's registry-emission enforcement in the body bullet) together provide the coordination that gate-skeptic's Recommendation 1 omits. gate-skeptic's Recommendation 1 and cross-principle-coherence's Recommendation 1 must be adopted together, not independently: gate-skeptic fixes the WORDING of what is required; cross-principle-coherence fixes the ENFORCEMENT MODE of what happens when it is violated. gate-skeptic should yield on the claim that XVI's constraint is self-contained and consistent with XV without a coordination clause; cross-principle-coherence should acknowledge that XVI's content-vs.-plumbing distinction is useful framing, even if the enforcement chain requires explicit XV coordination.

- **Effect of strengthening the plugin output MUST without enforcement-mode carve-out**
  - **gate-skeptic claims**: Recommendation 1 (P1) proposes replacing the design-intent paragraph's glosses with mechanical paraphrases, including "every numerical recommendation field in plugin output has an adjacent string-typed explanation field" — a mechanically stronger formulation of XVI's plugin output requirement, with no enforcement-mode qualification.
  - **cross-principle-coherence claims**: Recommendation 1 (P1) is the single most important recommendation: "A plugin recommendation that omits plain-language pairing is treated as malformed plugin output under Principle XV's warn-and-continue protocol; it DOES NOT block core deliberation execution." The risk if ignored: "A future implementor adds schema-level rejection of non-paired plugin output, triggering a core execution failure — a direct XV violation — while citing XVI's MUST as justification." (Actionable Recommendations, Recommendation 1)
  - **Why this is dangerous**: If gate-skeptic's Recommendation 1 is adopted in isolation — without cross-principle-coherence's enforcement-mode carve-out — the result is a version of Principle XVI with a MORE mechanically precise MUST on plugin output format and NO XV warn-and-continue coordination. This is strictly worse than the current candidate on the XV/XVI conflict that cross-principle-coherence identifies as the most dangerous unresolved issue. gate-skeptic did not audit the XV/XVI interaction at all; its Alignment section notes that XVI's constraint is "consistent with XV" but does not examine what happens at runtime when a plugin fails to comply. Adopting gate-skeptic's P1 fix without cross-principle-coherence's P1 fix produces a candidate that has passed gate-skeptic's audit but introduced the production failure mode cross-principle-coherence identified.
  - **Suggested resolution**: Both Recommendation 1s must be adopted together as a single integrated change. The implementation order should be: (a) add cross-principle-coherence's enforcement-mode clause to XVI's body ("violations trigger XV's warn-and-continue; DOES NOT block core execution"); (b) then apply gate-skeptic's mechanical paraphrase to the design-intent paragraph, ensuring the paraphrase references the enforcement clause or XV explicitly. Neither fix is sufficient alone; adopting gate-skeptic's alone is actively harmful on cross-principle-coherence's P1 concern.

  - **Coordination needed**: Synthesis should treat both as P1 and adopt both sets of fixes.

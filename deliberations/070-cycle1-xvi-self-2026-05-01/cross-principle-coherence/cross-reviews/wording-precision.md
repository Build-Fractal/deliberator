### Dangerous Contradictions

- **Verification metadata location: remove from body vs. add structured block to body**
  - **wording-precision claims**: The self-attestation sentence at L790 should be removed from the principle body entirely (Rec 1, P1). "No principle in I-XXVIII contains such a self-attestation of criteria compliance in its normative body text." The SIR is "the established home for this content."
  - **cross-principle-coherence claims**: A structured `Verification (v2.6.0):` block should be added to XVI's principle body (Rec 4, P2). "SIRs are preserved for audit trail but are comment blocks; the principle body is what future readers and agents load as constitutional text. Keeping verification evidence only in the SIR makes compliance audits dependent on reading comment blocks."
  - **Why this is dangerous**: The underlying philosophical positions are genuinely opposed. wording-precision holds that criteria-compliance metadata belongs exclusively in the SIR; cross-principle-coherence holds that verification evidence must be in the principle body to be self-contained. An implementation that adopts both recommendations produces a principle body with a formal Verification block present (CPC Rec 4) but without the informal attestation sentence (WP Rec 1) — which is internally coherent at the outcome level but not at the philosophical level. More critically: if wording-precision's position prevails (SIR-only), cross-principle-coherence's Rec 4 is rejected and future readers cannot verify the "mechanically verifiable" claim from the body alone; if cross-principle-coherence's position prevails (body must contain verification), wording-precision's rationale for Rec 1 — "SIR is the established home" — is weakened, because the principle body now hosts a verification block that wording-precision would classify as SIR-category content. A synthesis that simply accepts both without resolving the philosophical disagreement will produce governance inconsistency for the next amendment.
  - **Suggested resolution**: Adopt the outcome that both positions can accept (structured block over informal attestation) while explicitly resolving the philosophical disagreement in the governance record: the `Verification:` block is a formally sanctioned body-content type established by the gate's Extension blocks paragraph, and is distinct from informal self-attestation prose in a normative paragraph. This accepts wording-precision's specific objection (remove the informal sentence) and cross-principle-coherence's structural concern (body must contain formal verification evidence) without requiring either philosophical position to yield entirely. The gate's existing `Verification:` block requirement in the Extension blocks paragraph provides the textual warrant for this resolution.

- **Priority assignment for the plain-language pairing enforcement gap**
  - **wording-precision claims**: Missing enforcement sub-bullets for shape determinism and plain-language pairing is P2 — and conditionally drops to P3 if Rec 1 (self-attestation removal) is adopted. "If recommendation 1 is adopted, this recommendation drops in priority to P3 — the body no longer asserts verifiability for all three requirements, so the asymmetric enforcement coverage becomes less problematic" (Rec 4).
  - **cross-principle-coherence claims**: The enforcement mode for the plain-language MUST is P1 — the highest-priority finding. "Without this sentence, XVI's MUST and XV's 'MUST NOT block' are in silent conflict... A future implementor adds schema-level rejection of non-paired plugin output, triggering a core execution failure — a direct XV violation — while citing XVI's MUST as justification" (Rec 1).
  - **Why this is dangerous**: wording-precision treats the plain-language pairing enforcement gap as a documentation and verifiability problem — the question is whether automated checks are described in the body. cross-principle-coherence treats it as a runtime behavioral conflict — the question is what happens at execution time when a plugin violates the MUST. These are different problems, and acting on wording-precision's Rec 1 (remove self-attestation, dropping enforcement sub-bullets to P3) leaves cross-principle-coherence's P1 concern entirely unaddressed. An implementation of wording-precision's full recommendation set produces a principle body with no enforcement sub-bullets for plain-language pairing AND no enforcement mode clause specifying warn-and-continue. The XV↔XVI runtime conflict identified by cross-principle-coherence remains, and the absence of enforcement sub-bullets (wording-precision's secondary concern) makes it worse, not better.
  - **Suggested resolution**: Cross-principle-coherence's Rec 1 and wording-precision's Rec 4 address different layers and are not mutually exclusive. The synthesis should treat CPC's Rec 1 as independent of WP Rec 1's adoption status — the enforce-mode sentence must be added regardless of whether the self-attestation sentence is retained or removed, because the XV↔XVI conflict is operational, not documentary. WP Rec 4's priority should not be downgraded on the basis that WP Rec 1 is adopted; the body still needs enforcement evidence even if the self-attestation sentence is removed.

- **XVI's authority to MUST-require plugin output format: uncontested vs. an ungrounded assumption**
  - **wording-precision claims**: Treats XVI's MUST on plugin output format as uncontested jurisdiction, proposing to add Enforcement and Falsification sub-bullets reinforcing it within XVI's body (Rec 4): "A PR that adds a numerical recommendation field without an adjacent plain-language explanation field violates this principle." The review never questions whether XVI has authority to impose this requirement on plugin output.
  - **cross-principle-coherence claims**: "XVI has unilateral jurisdiction to MUST-require plugin output format" is an off-base assumption (Off-Base Assumptions section). "Plugin recommendations are plugin output — that places the constraint in XV's domain... XV governs what plugins can and cannot do with their output, including the warn-and-continue enforcement model. The MUST is orphaned from the enforcement mechanism that would give it operational meaning."
  - **Why this is dangerous**: If wording-precision's enforcement sub-bullets are added to XVI's body reinforcing the MUST, the resulting amendment has more text asserting XVI's unilateral authority over plugin output — and still no cross-principle coordination with XV. The sub-bullets would read as self-contained within XVI while the operational machinery lives in XV and is not referenced. Worse: wording-precision's Rec 4 Falsification sub-bullet ("A future PR that adds a numerical recommendation field without an adjacent plain-language explanation field violates this principle") makes the violation belong to XVI. A future compliance reviewer citing this sub-bullet against a violating plugin PR would be correct constitutionally but wrong operationally — the correct response is XV's warn-and-continue, not a XVI compliance failure that (implicitly) blocks execution.
  - **Suggested resolution**: Cross-principle-coherence's Rec 1 (add warn-and-continue cross-reference to XV) should be treated as a prerequisite for wording-precision's Rec 4 enforcement sub-bullets. The sequencing is: first establish that violations are handled by XV's enforcement machinery (CPC Rec 1), then add verifiability sub-bullets that reference that machinery (WP Rec 4 revised to cite the XV enforcement mode). The Falsification sub-bullet proposed by WP Rec 4 can be retained but should be scoped: "violates this principle's output-pairing requirement and is handled as malformed plugin output per Principle XV's warn-and-continue protocol."

### Systemic Contradictions

- **Evidence standards for closing security concerns on merged PRs**
  - **Manifests in**: The concurrent re-raise debate (pragmatist's burden-shift vs. skeptical's answer-or-file); the OAuth closure dispute (pragmatist attempted to close on a factual premise neither had verified); pragmatist's New Rec 1 framing the OAuth code-path verification as a synthesis prerequisite; the Q1 sub-questions left as deliberation invitations in SESSION-REVIEW.md rather than answered or filed.
  - **Root cause**: SESSION-REVIEW.md's Q3 acceptance bar specifies RECOMMENDED-fix or filed-as-new-issues for already-merged PRs but provides no closure standard for security concerns that are neither clearly confirmed nor clearly refuted. The Q1 sub-questions were posed as deliberation invitations, implicitly delegating the finding decision to the deliberation rather than the review. This created a recurring meta-dispute about when a concern is "answered enough" to close.
  - **Implication for spec**: Future session reviews that identify security sub-questions on merged PRs should classify each question at point of identification: (a) confirmed finding → file issue, (b) answered-negative-with-evidence → close with stated rationale, (c) genuinely unknown → characterize what would resolve it. The Q1 format ("Are there security implications of…?") delegates rather than classifies and should be replaced with a structured finding table matching the PR review table format.

- **Pre-emptive vs. just-in-time test writing under Principle XXVIII**
  - **Manifests in**: Skeptical's Rec 7 (multi-pattern test for a currently-singleton tuple); the broader discussion of test coverage for the 1KB boundary (where both agents agreed); the PR #56 test-2 interface-vs-behavior gap (skeptical identified it; pragmatist classified it as low impact and out-of-scope for the CLI test file).
  - **Root cause**: Principle XXVIII test-fix discipline requires tests written against known behavioral gaps with a failing scenario to validate the test itself. This creates real tension when the code contains "future-proof" paths (the singleton tuple, the 1KB boundary) that are structurally present but not yet exercised. The principle's application to partially-exercised code paths (where one entry is tested but multiple-entry iteration is not) is ambiguous.
  - **Implication for spec**: SESSION-REVIEW.md's PR #52 concern row flagged "Pattern is currently a singleton tuple; future-proof but not yet exercised" as a concern without a disposition. Principle XXVIII's §4.6 (added in PR #47) should explicitly address "latent path" testing — code that exists and is reachable but requires a second precondition (here, a second tuple entry) before it activates. The recommended disposition is PR-level convention: add the parametrized test at the PR that introduces the second entry, not proactively. This should be documented as an operational guidance note to avoid recurring debate.

- **Author-self-specification binding force**
  - **Manifests in**: The #53 trigger condition dispute (skeptical argued same-session triggers have less authority; pragmatist defended binding force of author-stated specifications); the override-with-rationale precedent (skeptical's Phase 1 argued the 2026-04-29 CONSTITUTIONAL_CONVERSATIONS.md entry stated the override criterion with "analogous acknowledged residuals" without quoting the IX text, suggesting the author characterized the override loosely); the Q3 acceptance bar in SESSION-REVIEW.md itself ("ACCEPT findings on the override-with-rationale precedent are explicitly DEFER-eligible") pre-classifying deliberation outputs.
  - **Root cause**: The governance framework does not distinguish between specification constraints imposed externally (by prior governance artifacts) and those imposed by an author on their own work within the same session. Both skeptical's challenge to the #53 trigger and the override-with-rationale falsifiability concern trace to the same gap: the framework assumes constraint-setters and constraint-subjects are different agents, and lacks a validity standard for self-constraining actions.
  - **Implication for spec**: CONSTITUTION.md's amendment procedures, when updated with the quoted-text citation requirement (converged P2 action), should explicitly address the self-authored-constraint question: trigger conditions and override rationales stated by the amendment author in the same session carry the same weight as externally-stated constraints, provided they are logged in the governance artifacts. This closes the "no prior policy weight" argument skeptical raised (and withdrew) before it recurs.

- **Governance formalization on first occurrence vs. precedent accumulation**
  - **Manifests in**: The override-precedent Q3 question (promote to constitutional principle vs. keep as governance-log artifact); pragmatist's defense of single-line anchor over skeptical's independent pre-deliberation gate; skeptical's Rec 6 withdrawal following pragmatist's "disproportionate for a one-time precedent" argument; the underlying question of when a governance mechanism has fired enough times to warrant constitutional elevation.
  - **Root cause**: The session review is asked to evaluate a precedent that has fired exactly once. There is no threshold in CONSTITUTION.md for when a governance-log artifact should be promoted to a constitutional principle. The absence of this threshold produced four recommendations spanning a range from "governance-log only" to "new constitutional principle with independent pre-deliberation gate" — all defensible under the current governance structure.
  - **Implication for spec**: The converged output (single-line anchor in the Governance → Amendments section with quoted-text citation) is the right disposition for a one-time precedent. CONSTITUTION.md should add a meta-governance note: a mechanism recorded in the governance log is considered for spec elevation after its second firing. This prevents both premature formalization (adding overhead for one-time events) and indefinite deferral of necessary formalization (perpetually "waiting for the right time").

- **Post-merge review scope: exhaustive pass vs. actionable triage**
  - **Manifests in**: The difference in recommendation counts between the two agents (7 vs. 5 in Phase 1); pragmatist's explicit statement that "defects now go into new issues, not into a re-review"; skeptical's identification of Bug 3b severity under-classification, PR #56 test-2 interface gap, and version bump smoke test as gaps the original author missed; the framing of the session review itself (Q1 asks "did I miss anything?" rather than "file new issues for what I missed").
  - **Root cause**: SESSION-REVIEW.md's acceptance bar for already-merged PRs is "RECOMMENDED-fix or filed as new issues; they do not block this deliberation's verdict." This correctly specifies the output type (issues, not blocks) but does not specify the completeness standard — exhaustive enumeration of all gaps or triage to the highest-value gaps. The two reviewers resolved this ambiguity differently, producing systematically different recommendation volumes.
  - **Implication for spec**: The acceptance bar for merged-PR findings in future session reviews should specify the review model explicitly: "findings on merged PRs are triaged to highest-value actionable gaps (not exhaustive enumeration); the standard is whether a gap, if not filed, creates a predictable regression path within the next two sessions." This is consistent with the pragmatist triage model that produced the 1KB adversarial test as P1 (clear regression path) while excluding the PR #56 engine-side behavioral assertion (no imminent regression scenario). Adopting this standard explicitly would prevent the divergence in review depth framing from recurring.

  - **Arguments**: Skeptical argues "valid when X" makes X a sufficient but not necessary condition for validity — a future override author can assert validity on other grounds without the quoted-text requirement, defeating the falsifiability purpose. "Must quote" is a categorical prohibition. Pragmatist's language was likely intended to merge both requirements but does not enforce the falsifiability requirement in edge cases where other validity criteria are asserted.
  - **Synthesizer assessment**: Skeptical's position is analytically stronger. The purpose of the requirement — agreed by both agents — is to make uniformity arguments falsifiable without independent research. "Valid when X" fails this test: it defines a sufficient condition for validity, not a necessary one. Under that framing, an override without quoted text is not necessarily invalid — it may be valid on other grounds. "Must quote X" creates a categorical obligation. Pragmatist's formulation correctly describes the intent but incorrectly encodes the enforcement. However, skeptical's scope ("uniformity override claim specifically") is unnecessarily narrow — pragmatist's scope ("override with rationale" generally) is more robust and future-proof. The synthesizer adopts skeptical's mandatory framing with pragmatist's broader scope.
  - **Recommended resolution**: The CONSTITUTION.md anchor line should read: "Any override-with-rationale claim must quote the specific text of the existing principle that would be narrowed under the override; the quoted passage and rationale are logged in SIR, governance log, and spec status." This preserves: (1) pragmatist's broader scope (all override-with-rationale, not only uniformity overrides); (2) skeptical's mandatory framing ("must quote" not "valid when"); (3) both agents' discoverability requirement (spec-level anchor). The categorical prohibition is the non-negotiable; the scope question is resolved in pragmatist's favor.

Writing the test now requires speculating about what the second pattern will be and how it should interact with the detection logic.

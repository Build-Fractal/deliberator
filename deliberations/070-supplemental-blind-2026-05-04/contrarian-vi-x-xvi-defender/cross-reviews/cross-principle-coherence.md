### Dangerous Contradictions

- **VI: Full constitutional retention versus split-migrate along XVII taxonomy**
  - **cross-principle-coherence claims**: Recommendation 2 ("Apply Principle XVII taxonomy to VI migration routing") accepts migration as the right direction for VI but argues for routing precision — execution-logic sub-bullets (orchestration logic to SKILL.md, configuration to conversus.yml) go to SKILL.md operational guidance, contribution-guideline sub-bullets go to CONTRIBUTING.md. The review never argues VI should be retained wholesale.
  - **contrarian-vi-x-xvi-defender claims**: Recommendation 1 ("Retain Principle VI with directory-resolution clarification") argues VI should remain in the constitution entirely. The migration was "incorrectly decided unless the principled distinction is supplied." The proposed fix is a Clarification block naming the CI-detectable directories, not a routing split.
  - **Why this is dangerous**: If both recommendations are implemented simultaneously, VI's sub-bullets would be split across SKILL.md (execution-logic half, per CPC) AND the constitution (full principle body, per CVXD), with a Clarification block in the constitution and a XVII-classification routing table in the migration SIR. The authoritative source for VI's execution-logic content would be in two places — a direct XI violation. More critically, CVXD's directory-resolution Clarification block would be annotating a principle that CPC's recommendation partially migrated out, producing a partially-empty constitutional principle whose body references content now living in SKILL.md.
  - **Suggested resolution**: The underlying disagreement is about whether VI passes the gate as a whole or only passes Criterion 2 after a principled distinction with IX/XV/XXIV is articulated. Resolve this first: if CVXD's principled-distinction argument prevails (no distinction from IX/XV/XXIV is articulable), VI is retained per CVXD. If the distinction is articulable, CPC's split-migrate routing is the appropriate remediation. The two recommendations are not composable — one must be chosen as the primary outcome.

- **XVI status: Grandfathered-with-partial-upgrade annotation versus pre-refactor body was already gate-compliant**
  - **cross-principle-coherence claims**: Recommendation 1 ("Annotate XVI's grandfathering entry with partial-upgrade status") accepts XVI's grandfathered gate-failure status as the baseline and proposes layering a partial-upgrade annotation on top: the v2.3.2 extension content satisfies Criterion 1, but the original plain-language clause remains a Criterion 2 failure. The review operates within the existing grandfathering framework.
  - **contrarian-vi-x-xvi-defender claims**: In "Missed Opportunities" ("Pre-cycle-1 XVI body already satisfying Criterion 2"), the pre-cycle-1 XVI body contained three numbered falsifiable rules that independently satisfied Criterion 2 before the cycle-1 refactor. The cycle-1 refactor was "a defensive improvement, not a gate-required correction." This means XVI's gate-failure status in the grandfathering disclosure is contested at its root, not merely incomplete.
  - **Why this is dangerous**: CPC's annotation approach writes "v2.3.2 upgraded XVI's determinism-scope content to Criterion-1-compliant" into the governance record. CVXD's finding would require a different annotation: "XVI's body was Criterion-2-compliant before cycle-1; the grandfathering disclosure misdescribed the failure." These two governance log entries directly contradict each other about when XVI became compliant and whether the cycle-1 refactor was gate-required. Future amendment authors reading the governance log would encounter irreconcilable accounts of the same principle's history. The audit trail — which both reviews agree is critical to preserve — would be internally inconsistent.
  - **Suggested resolution**: Separate the historical question (was the pre-cycle-1 body gate-compliant?) from the current annotation question (what is XVI's current status?). CVXD's historical claim can be acknowledged as an audit trail finding without overturning CPC's annotation: "The pre-cycle-1 body satisfied Criterion 2 via three numbered falsifiable rules; the cycle-1 refactor improved headline clarity without materially changing gate compliance; the v2.3.2 extension further strengthened Criterion 1 via audit hooks. Current status: constitutionally retained, partially upgraded." This composite annotation reconciles both positions without requiring either to be declared wrong.

- **Criterion 2 standard: VI clearly fails on judgment-call grounds versus VI passes because no principled distinction from IX/XV/XXIV exists**
  - **cross-principle-coherence claims**: In "Off-Base Assumptions" ("VI is treated as a uniform gate-failure"), the review concedes the narrow point while reframing it: "VI fails Criterion 2 more cleanly than Criterion 1" — the "when the artifact drives behavior" trigger requires judgment for novel artifact types not in the known consumer list. The review accepts VI's Criterion 2 failure as real while challenging the Criterion 1 characterization.
  - **contrarian-vi-x-xvi-defender claims**: In "Verdict-Relevant Summary" for VI, the review argues the Criterion 2 failure is not established: "A principled gate application cannot distinguish VI on Criterion 2 grounds without also failing IX, XV, and XXIV. The migration case has not articulated this distinction." The review rates the migration as "incorrectly decided" unless the principled distinction is supplied. VI passes Criterion 2 on the same standard applied to retained principles.
  - **Why this is dangerous**: The Criterion 2 standard cannot simultaneously mean "VI clearly fails because its trigger requires judgment for novel cases" (CPC) and "VI passes because the same judgment requirement exists in IX/XV/XXIV and no principled distinction has been articulated" (CVXD). If both are adopted, the gate's Criterion 2 test has two incompatible operationalizations: one where judgment-requirement alone grounds failure, and one where judgment-requirement grounds failure only if distinguishable from analogous retained-principle qualifiers. Future amendments would not know which standard applies. A principle like IX's "when framework or domain modeling requires them" would simultaneously pass (per CPC's standard: retained) and be at risk (per CPC's logic: judgment required for novel cases).
  - **Suggested resolution**: This is the deepest contradiction and requires the arbiter to rule on the Criterion 2 standard. CVXD's "principled-distinction documentation" requirement (Recommendation 4) is actually a procedural way to surface this: require migration specs to articulate the distinction. If the distinction cannot be articulated for VI without also condemning IX/XV/XXIV, the Criterion 2 failure was not established. CPC's Recommendation 4 ("Require principled-distinction documentation for Criterion 2 judgment-call migrations") is independently convergent with this approach, making it the natural resolution mechanism even though CPC accepts VI's failure and CVXD contests it.

- **Migration legitimacy as the operative frame: routing-improvement versus retention-argument**
  - **cross-principle-coherence claims**: The entire CPC review operates within a frame that accepts migration of VI and X as justified and focuses on identifying routing failures within that justified migration. CPC's "Alignment" section explicitly validates the gate's grandfathering logic and the gate's worked examples as "correctly placed." Recommendations address migration quality, not migration legitimacy.
  - **contrarian-vi-x-xvi-defender claims**: Recommendation 5 ("Validate cycle 2A's document scope before citing its findings as gate assessment") directly challenges the migration's procedural legitimacy: cycle 2A reviewed a post-migration document and cannot constitute an independent gate assessment. The contrarian mandate of spec 070 §9 AC #5 was not satisfied by either prior deliberation. Migration legitimacy is contested, not merely the quality of its execution.
  - **Why this is dangerous**: CPC's Recommendation 8 ("Record the migration SIR stream-crossing findings explicitly") and CVXD's Recommendation 5 pull governance record requirements in opposite directions. CPC's recommendation produces documentation improving migration quality; CVXD's recommendation produces documentation potentially reversing the migration's basis. Both require governance log entries, but the entries tell fundamentally different stories. A downstream arbiter reading both would find: "migration routing needs improvement" (CPC) alongside "migration procedural legitimacy is contested" (CVXD). Acting on both simultaneously is impossible — you cannot both improve migration routing and contest whether migration was procedurally valid.
  - **Suggested resolution**: Phase the governance interventions. First, the arbiter rules on CVXD's procedural legitimacy challenge (did cycle 2A satisfy spec 070 §9 AC #5?). If yes, CPC's routing-improvement recommendations are operative. If no, the migration basis is contested and must be re-run before routing improvements are addressed. The procedural question is prior in the governance sequence; CPC's substantive quality improvements are second-order relative to whether the migration was properly authorized.

### Tensions

- **XVII as migration-router versus XVII as retention-argument**
  - **cross-principle-coherence's position**: CPC's Recommendation 2 and the "XVII taxonomy not applied to migration routing" missed opportunity use Principle XVII as a routing tool — it determines where migrated content goes (SKILL.md for execution logic, CONTRIBUTING.md for contribution guidelines). XVII improves migration quality by preventing stream-crossing.
  - **contrarian-vi-x-xvi-defender's position**: CVXD's Recommendation 2 also invokes XVII, but as a retention argument: "VII explicitly states 'A rule that is enforced at runtime is execution logic even if it also serves as a contribution guideline. The authoritative source MUST be in SKILL.md/references.'" Since VI's sub-bullets are execution logic, routing them to CONTRIBUTING.md violates XVII — which is why they should not be migrated at all.
  - **Nature of tension**: Both reviews read XVII correctly — the principle does establish that execution logic cannot live in CONTRIBUTING.md equivalents. But they draw opposite conclusions. CPC says: migrate VI, then route execution-logic sub-bullets to SKILL.md instead of CONTRIBUTING.md. CVXD says: since the content is execution logic and execution logic must live in SKILL.md, VI's constitution already puts it in the right place — retain it. The tension is that XVII constrains what CONTRIBUTING.md can hold, but the constitutional text of VI is not CONTRIBUTING.md. CVXD's XVII argument is actually stronger: XVII prohibits execution logic from CONTRIBUTING.md, and VI's current home (the constitution, consumed with SKILL.md) is not the problematic destination.
  - **Coordination needed**: CPC's split-migrate recommendation and CVXD's retention recommendation are both XVII-consistent but at different levels of analysis. They can coexist if the outcome is: execution-logic sub-bullets of VI stay constitutional (CVXD position), while CPC's XVII-classification table requirement becomes the procedural gate that prevents future migrations from routing execution logic to contribution documents. The two uses of XVII are compatible at the level of process design, even if not at the level of VI's specific fate.

- **Principled-distinction requirement: procedural gate versus substantive argument**
  - **cross-principle-coherence's position**: Recommendation 4 ("Require principled-distinction documentation for Criterion 2 judgment-call migrations") proposes a procedural rule: future migration specs must explicitly document why the migrated principle's qualifier fails Criterion 2 when analogous qualifiers in retained principles pass. CPC frames this as a process improvement applicable to all migrations, not as a determination of VI's fate.
  - **contrarian-vi-x-xvi-defender's position**: CVXD's "Missed Opportunities" ("Principled-distinction gap for Criterion 2 comparisons") argues this gap is substantive: "The migration case has not articulated this distinction." The absence of the distinction is cited as evidence that VI's migration was "incorrectly decided." CVXD's argument is that the principled distinction must be supplied now, and if it cannot be, the migration was wrong.
  - **Nature of tension**: CPC's procedural requirement, if adopted, would force the migration-of-VI record to produce or fail to produce the principled distinction. If the distinction cannot be produced, CVXD's conclusion (migration was incorrectly decided) would be validated by the CPC procedure. The tension is that CPC proposes a process tool that, if applied retroactively to the completed VI migration, likely vindicates CVXD's outcome. CPC may not have intended this — the recommendation is framed as forward-looking. But CPC's Recommendation 4 and CVXD's principled-distinction argument are substantively convergent in their evidentiary requirements.
  - **Coordination needed**: Make CPC's Recommendation 4 explicitly retroactive to the spec 070 VI migration. Require the migration SIR to supply the principled distinction now. This is the lowest-cost resolution: if the distinction is produced, both reviews are partially satisfied (CPC's process requirement met, VI's migration substantiated). If it cannot be produced, CVXD's conclusion is validated by CPC's own procedural standard. No independent ruling is needed — the procedure decides.

- **X's sub-bullet 3 and Principle V: deletion versus retained-sub-bullet in a retained principle**
  - **cross-principle-coherence's position**: Recommendation 3 ("Delete X's error-handling sub-bullet rather than migrate it") argues X's third bullet ("Errors should never pass silently — warnings are emitted for malformed output, missing documents, and edge cases") is substantively identical to V's third bullet and should be deleted during migration, not relocated to docs/output-conventions.md. An XI violation would result from two documents carrying the same rule.
  - **contrarian-vi-x-xvi-defender's position**: Recommendation 2 ("Retain Principle X under renamed headline 'Output Structure Invariants'") argues X should be retained wholesale, with its sub-bullets elevated as primary content. The review does not distinguish sub-bullet 3 from the others; the retention recommendation covers the full principle including its error-handling content.
  - **Nature of tension**: If X is retained (CVXD position), sub-bullet 3 is retained along with it. CPC then argues sub-bullet 3 creates an XI violation with V even within the constitution. The XI violation exists whether X is migrated or retained — V and X's bullet 3 would both be in the constitution. However, CVXD's "Missed Opportunities" section notes X's sub-bullets are independently CI-verifiable, and sub-bullet 3's warning-emission behavior is exactly such a check. CPC's XI violation concern would require X's bullet 3 to be deleted even under CVXD's retention scenario, weakening X's verifiability case by removing one of the four CI-checkable anchors.
  - **Coordination needed**: Resolve whether V's third bullet and X's third bullet are substantively identical or whether X's is a specialization of V's. V says "Output validation emits warnings for malformed output but does NOT block file writes." X says "Errors should never pass silently — warnings are emitted for malformed output, missing documents, and edge cases." X adds "missing documents" and "edge cases" — V does not enumerate these. If X's bullet 3 is a specialization rather than a duplicate, the XI concern evaporates and CVXD's retention is unaffected. If they are truly identical, CPC's deletion applies whether X is retained or migrated, and X's four CI-checkable anchors reduce to three. The distinction-versus-duplication question should be resolved textually before either recommendation is adopted.

- **XVI refactor evaluation: missed opportunity finding versus decisive argument for governance log correction**
  - **cross-principle-coherence's position**: In "Missed Opportunities" ("Path (c) traded one ambiguity for another in XVI"), CPC notes the refactored headline ("Parameter pinning prevents cross-run drift in the assembled objective function") introduces new ambiguities ("drift," "assembled") without net Criterion 2 improvement. This is framed as a missed opportunity — the refactor was a wash — but CPC does not argue the refactor should be reversed or that it was improperly done.
  - **contrarian-vi-x-xvi-defender's position**: In "Missed Opportunities" ("Pre-cycle-1 XVI body already satisfying Criterion 2"), CVXD argues the pre-cycle-1 body's three numbered rules independently satisfied Criterion 2 and the refactor was "redundant, not gate-required." Recommendation 3 calls for a governance log correction: re-characterize the refactor as a defensive improvement, not a gate-required fix.
  - **Nature of tension**: Both reviews agree the refactor traded one ambiguity for another and may not have improved gate compliance. But CPC frames this as an incidental observation about the refactor's quality, while CVXD uses it as the basis for a governance log correction with institutional implications. The tension is scale: CPC's finding is a quality observation; CVXD's finding is a precedent-setting governance claim. CVXD's governance log correction, if adopted, changes the precedent: future reviewers would see that a principle with an ambiguous headline whose body is specific does not require headline refactoring. CPC's finding, if adopted alone, is an editorial note with no precedential weight.
  - **Coordination needed**: If CVXD's governance log correction (Recommendation 3) is adopted, CPC's "missed opportunity" finding should be folded into the same log entry as supporting evidence. The two converge on the factual finding (the refactor was a wash) and diverge only on whether the log entry should be precedent-setting. Making the log entry explicitly precedential (per CVXD) while noting the quality observation (per CPC) satisfies both without requiring either to yield.

- **Audit trail record types: XVII-classification tables versus contrarian argument entries**
  - **cross-principle-coherence's position**: Recommendation 8 ("Record the migration SIR stream-crossing findings explicitly") requires that every migration SIR include a XVII-classification table for each migrated sub-bullet: `| Sub-bullet text | XVII classification | Migration destination | Validation |`. This is a migration-process documentation requirement.
  - **contrarian-vi-x-xvi-defender's position**: Recommendation 7 ("Enter contrarian findings in governance log regardless of migration outcome") requires CONSTITUTIONAL_CONVERSATIONS.md entries documenting the pass-argument and counter-argument for each principle's gate assessment. This is a deliberation-process documentation requirement.
  - **Nature of tension**: Both recommendations are independently sensible, but together they create parallel documentation requirements for every migration: a XVII-classification table in the migration SIR (CPC) AND a contrarian-argument entry in CONSTITUTIONAL_CONVERSATIONS.md (CVXD). The tension is not that they conflict but that they pull amendment authors toward different documentation artifacts. Under time pressure, authors may satisfy one requirement while treating the other as administrative overhead. The requirements have different audiences — migration SIRs are read by implementation engineers, governance logs are read by constitutional reviewers — which makes them complementary but difficult to maintain together without discipline.
  - **Coordination needed**: Make the XVII-classification table a required appendix in CONSTITUTIONAL_CONVERSATIONS.md deliberation entries, not just in migration SIRs. This consolidates both requirements into a single document that both audiences must consult, reducing the dual-maintenance burden while preserving the distinct content each review identified as critical.

  - **Confidence level**: Medium. The agreement on the problem is high-confidence; the optimal remedy requires coordination between the two proposals rather than independent adoption of either alone.

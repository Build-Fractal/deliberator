### Systemic Contradictions

- **Migration process has no mandatory contrarian-assessment step before closure**
  - **Manifests in**: Unresolved Dispute 1 (X path-(c) vs. migration settled); C5/GN2 convergence (cycle 2A procedural standing); CVXD Rec 4 (principled-distinction documentation requirement); the entire structure of this deliberation being commissioned as a supplemental blind review.
  - **Root cause**: The Governance section's migration process ("a separate, intentional act governed by the same amendment process, with the receiving document identified explicitly in the migration spec") specifies what migration requires but not the procedural steps that make migration legitimate. There is no requirement for an independent contrarian assessment before migration closes, no prohibition against reviewing a post-migration document and treating the result as the primary gate assessment, and no defined path-taxonomy that makes "surgical clause migration" a named option rather than an ad hoc exception. Spec 070 §9 AC #5 required a contrarian assessment, but the constitution's own amendment text does not mandate this as a durable process requirement.
  - **Implication for spec**: The Governance section's migration process clause should be amended to require: (a) a path taxonomy definition in every migration SIR (G3); (b) an independent contrarian assessment performed on a document containing the principle being assessed (C5); and (c) a XVII-classification table documenting routing decisions for each sub-bullet (unanimous convergence). Without these structural requirements, the same procedural gap will recur in future migrations of grandfathered principles.

- **XVII taxonomy is the authoritative routing framework but is not enforced in migration SIRs**
  - **Manifests in**: Resolved contradiction 4 (CONTRIBUTING.md vs. SKILL.md destination for VI); Dispute 2 (X error-handling sub-bullet routing); unanimous convergence on the XVII classification table; CPC Recs P2 and P8; GF Recs G1 (modified) and GN1.
  - **Root cause**: The gate text's Governance section states "routing decisions to operational guidance follow XVII's execution-logic vs. contribution-guidelines distinction" (gate cross-reference to XVII), but the migration SIR format has no structural requirement to apply XVII classification to each migrated sub-bullet before routing. The cross-reference is advisory-by-practice rather than structurally enforced. Both VI migration decisions (to CONTRIBUTING.md) and the initial X routing assumption (to docs/output-conventions.md) were made without XVII classification, and both produced routing errors.
  - **Implication for spec**: The migration process clause should require a XVII-classification table as a mandatory element of every migration SIR, with explicit columns for XVII classification, required destination document, and normative strength. This converts the gate text's cross-reference from advisory to structurally enforced. GF's internal inconsistency (endorsing XVII as the routing framework in Alignment while proposing CONTRIBUTING.md as the destination in Recommendation 1) demonstrates that advisory cross-references are insufficient without structural enforcement.

- **Grandfathering disclosure is a static snapshot rather than a living compliance record**
  - **Manifests in**: P1 (XVI partial-upgrade annotation); C3 (XVI cycle-1 refactor characterization); GF Rec G4 (XVI clause map must land in same amendment as disclosure); CPC Rec P6 (distinguish VI's Criterion 1 and 2 failure modes); GF Rec G8 (XVI criterion priority must be documented).
  - **Root cause**: The grandfathering disclosure (added in v2.4.0) assigned VI, X, and XVI uniform gate-failure labels without criterion-specific attribution (the labels "judgment-laden," "irreducibly subjective," and "unverifiable" conflate Criterion 1 and Criterion 2 failure modes). The disclosure has no update mechanism — subsequent amendments that change a principle's gate status (such as XVI's v2.3.2 extension, which added mechanically-verifiable requirements satisfying Criterion 1 by the same standard as Principle XXIV) are not required to refresh the disclosure entry. The result is a disclosure that is guaranteed to become misleading over time as principles evolve.
  - **Implication for spec**: The disclosure format should require criterion-specific attribution (which of Criteria 1, 2, or 3 fail, and why); the amendment process should require disclosure refresh when an extension introduces new normative requirements that change a principle's gate status; and a CI lint (CPC Rec P7) should verify completeness and prevent silent addition of grandfathered principles without disclosure entries.

- **Gate calibration is asymmetrically failure-anchored**
  - **Manifests in**: Unresolved Dispute 4 (CPC's passing worked example); C8/PN2 convergence (headline-plus-body Criterion 2 clarification); the entire spec 070 supplemental deliberation structure being necessitated by calibration-driven over-migration pressure.
  - **Root cause**: The gate text provides two failure-only worked examples ("code should be readable" for Criterion 1; "all template variables MUST be lowercase" for Criterion 3) with no positive anchor for a principle that narrowly passes with an acknowledged residual. The XXVIII override-with-rationale precedent exists as an authoritative positive anchor but is not cited in the gate text. The Criterion 2 text can be read as requiring independently falsifiable headlines, which would disqualify IX, XII, XIII, XVII (all of which have summary headlines with specific bodies) — this headline-only misreading is a direct product of the calibration gap. Both calibration gaps (failure-only worked examples; headline-only Criterion 2 reading) systematically bias the gate toward over-migration of borderline-compliant principles.
  - **Implication for spec**: Two additions to the gate text would address both calibration gaps: (a) adding XXVIII as a positive worked example (CPC Rec P4); and (b) adding a sentence clarifying that Criterion 2 applies to the principle as a whole — headline and body together — so that a principle with an ambiguous headline and a specific body satisfies Criterion 2 through its body (CVXD Rec C8; CPC Rec PN2). These are low-cost additions that structurally reduce over-migration pressure without changing the gate's criteria.

- **Extension-block compliance history is not tracked in the grandfathering disclosure**
  - **Manifests in**: P1 (XVI partial-upgrade annotation); C3 (pre-cycle-1 body already gate-compliant); GF Recs G4, G8; unanimous convergence on XVI mixed status; GF's Alignment section on XVI's v2.3.2 upgrade.
  - **Root cause**: The grandfathering disclosure is a snapshot of gate status as of v2.4.0. The constitution's Governance section states that extension blocks added after the gate's ratification "MUST include the structured `Verification:` block (Criterion 1) when they introduce new normative requirements." But this requirement does not trigger a disclosure refresh — a principle can accumulate mechanically-verifiable extension content that brings it closer to gate compliance without the disclosure ever reflecting this.

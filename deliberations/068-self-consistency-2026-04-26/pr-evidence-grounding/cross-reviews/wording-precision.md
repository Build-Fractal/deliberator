### Cross-Review of wording-precision by pr-evidence-grounding

wording-precision and I converged on the same fault line in v2.3.2 — that the candidate's central pinning rule is asserted as if it were already operating, when in fact the wording is doing several jobs at once (descriptive, normative, falsificatory) and none of them sharply enough. We arrived from different angles: wording-precision through the lens of normative-verb auditing, me through code-grounding against `conversus/schemas/construction.py` and spec 014. The agreements are substantive; the tensions are mostly about *which fix is load-bearing* rather than whether a fix is needed.

### Dangerous Contradictions

1. **wording-precision Recommendation #1 (promote pinning to MUST) vs my Off-Base #1 (no cache layer exists).** wording-precision's fix tightens the obligation language so a future PR can be measured against it. My finding is that even with a perfect MUST, there is no `cache` to "reuse" — the actual mechanism in spec 014 is `objective.yml` artifact persistence (write-once, re-read on subsequent invocations). If wording-precision's recommendation is applied verbatim ("Cached values from the first resolution MUST be reused"), the constitution mandates a mechanism that does not exist in the codebase, while my recommendation #2 ("persisted to `objective.yml`") would mandate the mechanism that does exist. **Resolution**: layer them — adopt wording-precision's MUST framing AND my artifact anchor, producing "Resolved parameter values MUST be persisted to `objective.yml` (spec 014 FR-012) for the duration of the run; the LLM MUST NOT be re-invoked for parameter resolution within the same run." Without combining, wording-precision's fix risks codifying a non-existent cache, and my fix risks soft language.

2. **wording-precision's "define deliberation run" (Rec #2) vs my "tie to a concrete artifact" (Rec #5).** Both reviews independently flagged that "per deliberation run" is undefined and operationally critical. wording-precision proposes a parenthetical definition citing "a single invocation of the run engine producing one output directory; retries within an invocation are part of the same run." I propose tying to `objective.yml` / output directory / `conversus.yml` invocation. These are compatible but not identical — wording-precision's "retries within an invocation are part of the same run" is a substantive claim about retry semantics that my version does not commit to. If the codebase uses a different retry boundary (e.g., orchestrator restart loses the cache), wording-precision's definition becomes false on adoption. **Resolution**: prefer wording-precision's definition phrasing, but anchor it to the artifact (per my Rec #5) so the boundary is observable rather than defined-by-fiat.

3. **wording-precision Off-Base #2 + Rec #3 (XVI ↔ VII reconciliation) vs my Off-Base #4 (no enforcement anywhere).** wording-precision argues VII vs XVI is a textual contradiction the v2.3.2 amendment only half-resolves, and proposes carving an explicit exception. I noted the same VII tension (my Missed Opportunity #9, my Rec #9) but characterized the deeper risk as enforcement-absent: there is no Pydantic validator, no CI gate, no test asserting within-run pinning. The dangerous interaction is that wording-precision's fix sharpens the rule on paper, but without my enforcement scaffolding, the sharper rule is *easier to violate silently* — a future PR can claim XVI compliance with no test to disprove it. **Resolution**: adopt wording-precision's textual carve-out AND my proposed CI lint / `SourceProvenance.filled_by` audit hook. The constitution should both name the rule precisely and name the enforcement surface.

### Tensions

1. **Scope of "what v2.3.2 was supposed to fix."** wording-precision treats v2.3.2 primarily as a *wording* amendment that needs ten textual tightenings. I treat it as a *grounding* amendment that needs verification against the codebase before merging, per spec 068 §7 Q1. Both framings are legitimate, but they suggest different merge orderings: wording-precision's fixes can land in v2.3.2 directly; my fixes arguably require either a code audit (preferred) or an "evidence-pending" hedge (interim). If both review sets are applied without sequencing, the candidate gets ten textual fixes and one "evidence-pending" hedge, which reads incoherently. **Suggested ordering**: do the code grep first, then apply wording-precision's tightenings against verified-true facts; the hedge becomes unnecessary.

2. **Missing v2.3.2 Sync Impact Report.** wording-precision flagged this in its Scope Creep Check (the top-of-file Sync Impact Report still describes v2.3.1, version footer says 2.3.2). I did not flag this. wording-precision is right that this is a precision/metadata gap. It interacts with my "evidence-pending" recommendation: if a v2.3.2 SIR is added, it is the natural place to record either the spec 068 §7 Q1 grep result or the explicit "aspirational" framing.

3. **"Stage 2 disambiguates two LLM activities" (wording-precision Rec #7) vs the `GapFiller` protocol shape (my Missed Opportunity #8).** wording-precision proposes splitting stage 2 conceptually into 2a (question generation) and 2b (answer→value extraction). I noted that `GapFiller` (construction.py:139-149) is the literal extension point and the question/extraction split may not match the protocol's actual surface. The tension is whether the constitution should name protocol-level boundaries (mine) or activity-level boundaries (wording-precision's). Without checking which call sites exist in `InteractiveGapFiller` and the future `LLMGapFiller`, either decomposition risks describing a phantom split. **Suggested resolution**: name the `GapFiller.fill()` boundary (one call) and let stochasticity be a property of that call, regardless of how many model invocations the implementation chooses internally — this matches both the code and wording-precision's "pinned together" intent.

4. **"Cross-run variance bound" framing (wording-precision Rec #5) vs "name the failure mode" (my Missed Opportunity #6).** wording-precision wants to bound what cross-run variance is acceptable (values yes, shape no). I want to name the concrete user-visible failure mode ("Two `/conversus mode` invocations on the same problem.md MAY produce different objective.yml files"). These are complementary but the candidate currently has neither — adopting only wording-precision's bound leaves the user without a concrete example; adopting only mine leaves the bound unstated. **Both should land.**

5. **"Specify pinning storage and lifetime" (wording-precision Rec #6) vs my artifact-anchor recommendation.** wording-precision suggests "persisted to the run's output directory and reused for the lifetime of that directory." I suggest naming `objective.yml` (the artifact spec 014 already defines). wording-precision's phrasing is mechanism-agnostic; mine is mechanism-specific. The risk with mine is that future implementations might split parameters into a separate file and the constitution would need re-amendment. The risk with wording-precision's is that "the run's output directory" is itself undefined. **Resolution**: cite `objective.yml` as the current location with a forward-compatible hedge ("or its successor parameter artifact").

### Safe Agreements

1. **The candidate's pinning rule is descriptive, not normative, and that is a real defect.** wording-precision's Rec #1 ("Promote pinning from description to obligation") and my Off-Base #1 ("the discipline is asserted as if already implemented") arrive at the same conclusion via different evidence. Both reviews independently identify lines 463-466 as the load-bearing weakness. This is the highest-confidence finding across both reviews.

2. **"Per deliberation run" is undefined and operationally critical.** wording-precision's Rec #2 and my Rec #5 land on the same defect. Both reviews flag this as P1/P2 and propose definitional anchoring. The agreement is strong enough that v2.3.2 should not merge without addressing it.

3. **VII ↔ XVI tension is real, not artifactual.** wording-precision's Off-Base #2 and my Missed Opportunity #9 / Rec #9 independently identify the cross-principle contradiction. Both reviews agree the v2.3.2 amendment was meant to resolve it and only half does. The textual fix (carve-out language) is uncontroversial; the enforcement question (covered in Dangerous Contradiction #3) is where we differ.

4. **The falsification clause (L496-498) is the strongest sentence in the amendment.** wording-precision's Alignment #1 calls it "unusually precise for a constitution"; my Alignment #6 calls it "well-formed" and "enforceable by a hypothetical lint." Both reviews agree this sentence is the amendment's load-bearing precision win and should be preserved verbatim. The implication: when the surrounding text is tightened, the falsification clause should not be touched.

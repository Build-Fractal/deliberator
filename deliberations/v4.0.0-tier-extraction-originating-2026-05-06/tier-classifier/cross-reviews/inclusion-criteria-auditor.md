### Dangerous Contradictions

- **Grandfathering immunity vs. scope-based reclassification**
  - **inclusion-criteria-auditor claims**: "The most important issue is clarifying whether grandfathered principles retain immunity from gate re-evaluation during tier reclassification, or whether the MAJOR amendment re-opens constitutional inclusion review" (Executive Summary)
  - **tier-classifier claims**: Direct reclassification recommendations for multiple principles (VIII, IV, XII, XIII) without addressing grandfathering implications at all (Actionable Recommendations 1-4)
  - **Why this is dangerous**: If inclusion-criteria-auditor is correct that tier reclassification reopens gate review, then tier-classifier's reclassification approach could invalidate grandfathered principles that fail current gate criteria. If tier-classifier is correct that scope analysis justifies reclassification, then inclusion-criteria-auditor's procedural concerns could block substantively necessary corrections.
  - **Suggested resolution**: Address grandfathering explicitly before any reclassifications. Either establish that grandfathered principles retain immunity (allowing tier moves without gate re-review) or acknowledge that reclassification triggers gate evaluation and prepare for potential principle rejections.

- **Universal principle verification scalability**
  - **inclusion-criteria-auditor claims**: "Universal principles require verification 'across every Build Fractal product' but existing mechanisms are conversus-specific" and recommends enumerating which Universal principles need verification updates (Actionable Recommendations 2, 6)
  - **tier-classifier claims**: Principles VIII and IV should move from Universal to Suite tier specifically because "The principle addresses 'mechanical template-driven behavior over LLM inference' which is specific to AI/LLM systems" and "Prompt-orchestration is conversus-specific" (Actionable Recommendations 1, 2)
  - **Why this is dangerous**: One solution fixes the verification mechanisms to work universally; the other solution moves the problematic principles to a narrower scope. Both cannot be implemented simultaneously for the same principles. The approaches are mutually exclusive.
  - **Suggested resolution**: Determine whether Universal-classified principles with conversus-specific verification should have their verification generalized (inclusion-criteria-auditor approach) or should be reclassified to Suite tier (tier-classifier approach). Likely requires case-by-case analysis.

- **Amendment scope and complexity**
  - **inclusion-criteria-auditor claims**: Focus on "explicit language to the Sync Impact Report" clarifications and verification protocol additions while preserving existing classifications (Missed Opportunities section)
  - **tier-classifier claims**: "4-5 principles require reclassification" with specific tier moves recommended as "Priority: P1" and "Priority: P2" changes (Executive Summary, Actionable Recommendations)
  - **Why this is dangerous**: One approach treats this as primarily a procedural clarification amendment; the other treats it as a substantive reclassification amendment. The scope difference affects the entire verification and ratification process.
  - **Suggested resolution**: Determine whether v4.0.0 should be a conservative tier-extraction (inclusion-criteria-auditor) or include substantive reclassifications (tier-classifier). If both are needed, consider splitting into two amendments to avoid bundling procedural and substantive changes.

### Tensions

- **Procedural vs. substantive analysis priorities**
  - **inclusion-criteria-auditor's position**: Prioritizes Constitutional Inclusion Criteria compliance, gate re-evaluation triggers, and verification mechanism scalability (Actionable Recommendations focus on procedural clarity)
  - **tier-classifier's position**: Prioritizes actual scope-to-tier alignment with specific reclassification recommendations based on principle content analysis (Actionable Recommendations focus on tier boundary corrections)
  - **Nature of tension**: Both are necessary but procedural correctness and scope accuracy can conflict when current procedures would preserve misclassifications or when scope corrections violate procedural constraints.
  - **Coordination needed**: Establish whether procedural compliance takes precedence over scope accuracy, or develop a framework that satisfies both (e.g., scope corrections with explicit grandfathering impact analysis).

- **Amendment verification burden**
  - **inclusion-criteria-auditor's position**: Recommends six detailed verification requirements including "cross-tier distinctness audit" and "tier-specific verification artifact enumeration" (Actionable Recommendations 3, 2)
  - **tier-classifier's position**: Recommends eight changes including multiple principle reclassifications plus "Document Tier Assignment Criteria" and "Cross-Reference Principle Dependencies" (Actionable Recommendations 7, 8)
  - **Nature of tension**: Both approaches significantly increase verification complexity but in different directions - one adds procedural safeguards, the other adds substantive changes plus new documentation requirements.
  - **Coordination needed**: Assess total verification burden of combined approaches and prioritize essential elements to prevent amendment failure due to excessive complexity.

- **Universal tier interpretation**
  - **inclusion-criteria-auditor's position**: Accepts current Universal classifications while requiring verification mechanisms that work "across every Build Fractal product" (Actionable Recommendation 2)
  - **tier-classifier's position**: Questions whether several Universal-classified principles actually apply to non-conversus products, suggesting Suite tier is more appropriate (Missed Opportunities, Off-Base Assumptions)
  - **Nature of tension**: One assumes Universal scope is correct and fixes verification; the other questions Universal scope based on principle content. Both valid but incompatible starting points.
  - **Coordination needed**: Establish criteria for true Universal applicability vs. principles that only seem universal but are actually conversus-suite-specific in practice.

- **Gate criteria application timing**
  - **inclusion-criteria-auditor's position**: Emphasizes that "tier reclassification re-opens the gate for grandfathered principles" as a critical ambiguity requiring resolution (Missed Opportunities)
  - **tier-classifier's position**: Implicitly assumes reclassification based on scope analysis is valid without addressing gate re-evaluation implications
  - **Nature of tension**: Timing question - should scope analysis precede gate evaluation, or should gate compliance be verified before scope adjustments are considered?
  - **Coordination needed**: Sequence the evaluation steps clearly: either scope-first-then-gate or gate-compliance-first-then-scope, with explicit rationale for the chosen order.

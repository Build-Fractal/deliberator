### Final Position Statement

**Non-Negotiables**

1. The XVI/XV composition gap MUST be resolved in the receiving document, not left as a behavioral ambiguity. Wherever the plain-language requirement lands — excised to AGENTS.md or retained with an in-place patch — the document MUST explicitly state that non-conforming plain-language output does not block core deliberation and is handled under Principle XV's warning-and-continue semantics. This is non-negotiable because the gap is not an editorial question: it specifies the runtime behavior of a deployed system when a plugin emits non-conforming output. Without explicit specification, agents consuming the constitution as execution truth will diverge on this case. Both reviews identified this as a "dangerous contradiction" and both Phase 3 revisions addressed it; the synthesis cannot omit it without re-opening the contradiction.

2. The GapFiller.fill() atomicity requirement MUST be added to XVI's stage-2 specification as a mandatory clause, not relegated to operational guidance. This is non-negotiable because the existing prohibition ("the LLM MUST NOT be re-invoked for parameter resolution within the same run") creates an ambiguous failure mode — partial success before failure — where retry behavior is simultaneously required by practical robustness and prohibited by the letter of the existing text. Both reviews independently elevated this to P1; it is the one gap that both agents agree is unaddressed by any existing principle and that produces divergent implementation behavior without resolution. The atomicity clause closes the gap cleanly, is mechanically verifiable, and covers core execution (not plugin behavior), placing it squarely within XVI's scope.

**Flexibility**

1. The "assembly-form determinism" rename is my preferred outcome, but I am flexible on the exact alternative phrasing. What must be preserved: whatever term is chosen for XVI's structural requirement MUST be demonstrably distinct from Principle IX's "shape" vocabulary, so that a reader who has internalized IX's "shape tests are prohibited" does not encounter XVI's requirement as a contradiction. If the synthesizer finds a formulation other than "assembly-form determinism" that achieves this disambiguation — "structural-form determinism," "assembled-form determinism," "objective-form determinism" — that is acceptable. What is not acceptable: retaining "shape determinism" unchanged while IX's prohibition remains in the constitution.

2. My modified Rec 2(a) calls for adding a stage-3 verification artifact to XVI's enforcement block. I am flexible on whether this artifact is named as a CI lint, a contract test, or a formal property assertion — and I am flexible on whether it lands in XVI's body or in a structured addendum. What must be preserved: the artifact must be named concretely enough that an engineer reading XVI can sketch its implementation in one paragraph, and the naming must be accompanied by the SIR documentation recording the VII+VIII composition analysis (my surviving Rec 4). Both elements together close the Criterion 1 gap for stage-3 while honestly acknowledging its compositional character. If mathematical's Criterion 3 analysis gate is adopted by the synthesizer as a sequencing requirement, I accept that gate provided it includes a concrete deadline or trigger condition — "before the next MINOR amendment" or "before the stage-3 contract test PR opens" — rather than an open-ended deferral with no resolution mechanism.

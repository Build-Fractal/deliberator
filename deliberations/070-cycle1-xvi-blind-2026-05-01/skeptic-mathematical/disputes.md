### Final Position Statement

**Non-Negotiables**

1. **GapFiller.fill() atomicity requirement must be added to XVI's stage-2 description before this amendment is closed.** This gap is structurally real: the current prohibition on within-run re-invocation does not cover partial-fill failures, and implementations will diverge in a way that is both difficult to debug and silently permitted by the letter of the existing text. The fix is precise, the verification path is concrete (inject a partial-fill failure and assert the orchestrator rejects or retries rather than proceeding), and it is not addressed by any existing principle or by any other recommendation in this deliberation. (Mathematical revision, Rec 3 surviving; confirmed P1 by cross-principle New Rec 1.)

2. **The Criterion 3 analysis outcome must be formally documented before the headline restructuring is applied.** Even if the synthesizer accepts the reviews' safe agreement as the analysis conclusion (which I am open to), that conclusion must appear as a formal record — not merely as an informal convergence finding — because the headline structure follows directly from it. A constitution consumed as execution truth by agents must not contain an invariant (stage-3 in the two-invariants headline) whose normative status is established only by informal review convergence and not by a documented formal analysis. The record need not be elaborate: a three-sentence SIR entry stating the question, the evidence, and the conclusion satisfies the requirement. (Mathematical revision, New Rec 2 P2 and modified Rec 4.)

3. **The receiving document for the plain-language excision must explicitly state the runtime failure semantics before the excision is applied.** The XVI/XV behavioral contradiction does not resolve itself by moving the requirement to AGENTS.md. Wherever the requirement lives, agents consuming the specification must be told: non-conforming plain-language output does not block core deliberation, is preserved with a warning, and is governed by XV's warning-and-continue model. Specifying the location without specifying the runtime semantics leaves the dangerous behavioral ambiguity — a MUST-language requirement with undefined failure handling — intact in a different document. (Mathematical revision, New Rec 1 P1; cross-principle revision, modified Rec 1.)

**Flexibility**

1. **Headline restructuring wording** — I am flexible on the exact phrasing of the one-invariant headline, the cross-reference note for stage-3, and how the restructuring interacts with cross-principle's Rec 3 rename ("assembly-form determinism" substituted for "shape determinism"). What must be preserved: the headline enumerates exactly as many invariants as pass the Criterion 3 gate, with stage-3's presence (or absence) in the headline determined by the formal analysis record, not by artifact presence alone.

2. **Version-boundary edge case placement** — I am flexible on whether the version-boundary clause (Rec 7) appears in the constitution body, the Clarification v2.3.2 block, or the Governance section's "deliberation run" definition. What must be preserved: some authoritative text must address what happens when conversus is upgraded mid-run and must choose among the three options (complete using pre-upgrade binary, abort, or prohibit resuming pre-upgrade objective.yml with post-upgrade binary) rather than leaving the behavior implementation-defined.

3. **Stage-2 enforcement exit condition wording** — I am flexible on the exact marker syntax for the exit condition ("When the stage-2 contract test ships, restore 'is required' and remove this notice" vs. an equivalent formulation). What must be preserved: the two-step structure — (a) interim softening that accurately represents current enforcement status, and (b) explicit exit condition tied to the contract test shipping — rather than either unconditional hardening (which overpromises) or softening without an exit condition (which removes the pressure to ship the test).

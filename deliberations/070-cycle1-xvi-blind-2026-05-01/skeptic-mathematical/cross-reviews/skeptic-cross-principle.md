### Dangerous Contradictions

- **Plain-language requirement: excise vs. patch-in-place**
  - **skeptic-cross-principle claims**: "Add to XVI's plain-language pairing bullet: 'A plugin recommendation that includes numerical output without a conforming plain-language explanation is treated as invalid plugin output under Principle XV — the output is preserved with a warning and core deliberation continues.'" (Rec 1). The requirement stays in XVI; the fix is to resolve the XV/XVI composition gap by importing XV's warning-and-continue semantics.
  - **skeptic-mathematical claims**: "Remove requirement 3 from the Principle XVI headline and body. Relocate it to a dedicated section in AGENTS.md or an operational guidance document as a plugin authoring guideline." (Rec 1). The requirement leaves XVI because it fails Criterion 2 (falsifiable scope) regardless of how the failure semantics are resolved.
  - **Why this is dangerous**: If both positions are implemented simultaneously, the constitution would contain XVI text that treats plain-language pairing as an invalid-output signal under XV while AGENTS.md treats the same requirement as a non-normative authoring guideline. An implementor reading both would receive contradictory instructions about whether non-conforming output triggers a XV warning (blocking-with-continue) or is simply preferred practice. The XVI/XV resolution sketched by skeptic-cross-principle depends on the requirement being constitutionally enforceable; skeptic-mathematical's excision renders that resolution moot.
  - **Suggested resolution**: The diagnostic agreement is strong (both reviews find the plain-language requirement under-specified). The resolution dispute reduces to one question: can adding XV failure semantics rehabilitate Criterion 2 compliance? Skeptic-mathematical should yield if a minimum-sufficiency test for "plain-language" can be written that does not require reviewer interpretation — which skeptic-cross-principle's proposed text does not yet supply. Until that test exists, skeptic-mathematical's excision is the safer constitutional move. The cooperative path: skeptic-cross-principle supplies the falsifiable minimum-sufficiency test; if it can be written, the in-place patch survives; if it cannot, the excision wins.

- **Stage-3 determinism: keep in XVI vs. dissolve into VII+VIII**
  - **skeptic-cross-principle claims**: "Stage-3 deterministic assembly is VIII + VII applied to the optimization domain... The SIR should acknowledge this rather than treating stage-3 as independently distinct." (Off-Base Assumptions).   - **skeptic-mathematical claims**: Reconcile the two organizational frameworks (3 requirements vs. 3 stages) by restructuring the headline to explicitly reference the pipeline and making the stage-to-requirement mapping explicit (Rec 4). This implicitly retains stage-3 determinism as substantive content within XVI.
  - **Why this is dangerous**: If stage-3 is dissolved into a cross-reference to VII+VIII, skeptic-mathematical's Rec 4 restructuring becomes incoherent — the restructured headline it proposes would reference a stage whose normative content no longer lives in XVI. Conversely, if stage-3 is kept and given a verification artifact (skeptic-cross-principle's Option A), the dual-taxonomy problem skeptic-mathematical identifies (Rec 4, Missed Opportunities) persists. The two positions produce different final texts that cannot both be applied without producing a structural contradiction in the restructured headline.
  - **Suggested resolution**: The Criterion 3 analysis skeptic-cross-principle demands (SIR documentation) should be written first. If the analysis concludes stage-3 is not independently distinct from VII+VIII, the cross-reference option wins and skeptic-mathematical's Rec 4 should be narrowed to cover only the two remaining requirements (pinning + stage mapping). If stage-3 survives the Criterion 3 analysis, skeptic-mathematical's Rec 4 restructuring proceeds as drafted. The Criterion 3 question is logically prior; both reviewers should defer the structural reorganization until it is answered.

- **Enforcement language: soften the MUST vs. add a verification artifact**
  - **skeptic-cross-principle claims**: The stage-3 verification artifact gap is addressed by either naming a CI lint in XVI or dissolving stage-3 into VII+VIII (Rec 2).   - **Why this is dangerous**: If both positions are implemented, XVI would simultaneously declare enforcement "pending" (skeptic-mathematical's language change) and provide a named verification artifact (skeptic-cross-principle's CI lint). The artifact's existence contradicts the "pending" framing. Agents reading the principle would face inconsistent signals: the enforcement sub-bullet says "pending" but a specific lint check is named and presumably operational.
  - **Suggested resolution**: The contradiction is sequencing-dependent. Skeptic-mathematical's softening is the correct interim state (before the artifact ships); skeptic-cross-principle's artifact addition is the correct final state (after the artifact ships). Implement skeptic-mathematical's language change now with a clear "WHEN this lint exists, remove the 'pending' qualifier" note. Skeptic-cross-principle's verification artifact recommendation becomes the trigger condition for reverting the softened language — not an alternative to it.

### Tensions

- **Falsifiable scope: threshold for constitutional inclusion**
  - **skeptic-cross-principle's position**: The plain-language requirement is constitutionally flawed but addressable in-place. The fix imports XV semantics and adds schema-level enforcement. The Governance gate is not treated as an absolute bar — grandfathered status partially excuses the Criterion 2 failure (Missed Opportunities, "plain-language pairing has no schema-level enforcement"; Off-Base Assumptions, second item).
  - **skeptic-mathematical's position**: The plain-language requirement "fails the constitution's own falsifiable-scope gate" and is "indistinguishable from operational guidance dressed in constitutional language" (Executive Summary). Grandfathered status does not rehabilitate the requirement; it only explains why it was not caught at ratification time.
  - **Nature of tension**: Both positions agree on the diagnosis. They disagree about what follows from it. Skeptic-cross-principle treats the Governance gate as a quality signal that informs the fix design; skeptic-mathematical treats it as a dispositive criterion. This is not a logical contradiction but a different threshold for what "constitutionally unacceptable" means.
  - **Coordination needed**: The synthesis needs to declare whether the Governance gate (specifically Criterion 2) is a trigger for excision or a trigger for improvement. The gate's own text says principles that fail "belong in operational guidance" — which supports skeptic-mathematical's position. But the grandfathering clause says migration requires "a separate, intentional act governed by the same amendment process" — which supports skeptic-cross-principle's in-place patch as a lower-cost path. A cooperative framing: the in-place patch is an acceptable interim state IF AND ONLY IF a minimum-sufficiency test is written that makes the requirement falsifiable; absent that test, the excision proceeds.

- **GapFiller.fill() partial failure: unaddressed by both but framed differently**
  - **skeptic-cross-principle's position**: The XVI/XV composition gap is the primary failure-semantics problem. The proposed resolution (XV warning-and-continue for non-conforming plugin output) addresses the plugin output case but not the gap-filling case (Rec 1).
  - **skeptic-mathematical's position**: GapFiller.fill() partial failure is a distinct gap: "if `fill()` fails partway through, subsequent retries may see a partially-pinned state" and "re-invoking the gap-filler mid-deliberation in the letter of the prohibition" (Missed Opportunities, fourth item; Rec 3).
  - **Nature of tension**: Skeptic-cross-principle's proposed XVI text — "A plugin recommendation that includes numerical output without a conforming plain-language explanation is treated as invalid plugin output under Principle XV" — applies XV semantics to plugin output. Skeptic-mathematical's atomicity requirement applies to the gap-filling stage (stage 2), which is not a plugin. The two fixes target different system components, but skeptic-cross-principle's XV-import framing could mislead a reader into thinking the XV resolution covers gap-filling failures as well. It does not — gap-filling is core execution, not plugin execution.
  - **Coordination needed**: The synthesis should explicitly scope the XV resolution to plugin output (as skeptic-cross-principle intends) and add skeptic-mathematical's atomicity requirement for stage-2 as a separate, independent fix. The two fixes address different components and must not be collapsed into one.

- **Organizational framework: structural clarity vs. cross-principle coherence**
  - **skeptic-cross-principle's position**: The primary structural problems in XVI are cross-principle composition gaps (XVI/XV, XVI/VII, XVI/IX, XVI/VIII). The three-requirement vs. three-stage dual taxonomy is not raised.
  - **skeptic-mathematical's position**: The dual taxonomy (3 requirements vs. 3 stages, with no 1:1 mapping) is a P2 structural incoherence that "forces readers to mentally reconcile two competing taxonomies" (Missed Opportunities, second item; Rec 4).
  - **Nature of tension**: Skeptic-cross-principle's recommended text changes — particularly the XVI/XV resolution in Rec 1 — add new normative language to the existing framework without addressing the framework's organizational structure. Implementing Rec 1 without also implementing skeptic-mathematical's Rec 4 would make the dual-taxonomy problem worse: the principle would gain additional normative text while still presenting two competing organizational schemes to readers.
  - **Coordination needed**: The synthesis should sequence the organizational restructuring (skeptic-mathematical Rec 4) before or alongside the cross-principle resolution text (skeptic-cross-principle Rec 1). Adding new normative text to a structurally incoherent framework amplifies the incoherence. If stage-3 is dissolved into a cross-reference (skeptic-cross-principle's Option B in Rec 2), the restructuring in skeptic-mathematical's Rec 4 must be updated to reflect the reduced requirement count.

- **Template registry stability: silent dependency vs. unacknowledged gap**
  - **skeptic-cross-principle's position**: Does not raise template registry stability as a concern. The byte-identical claim is addressed through the headline scoping fix and stage-3 dissolution option (Recs 2 and 2 respectively).
  - **skeptic-mathematical's position**: "The template registry MUST be treated as immutable for the duration of a deliberation run... unstated dependencies in constitutional text are exactly what creates 'silent failures' (Principle X)." (Missed Opportunities, sixth item; Rec 6).
  - **Nature of tension**: Skeptic-cross-principle's scoping fix for the headline — adding "within a deliberation run, given a fully-pinned parameter set" — narrows the byte-identical claim but does not close the silent dependency gap. A plugin hot-reload during a run would still violate byte-identity under the scoped claim without violating any stated prohibition, which is exactly the gap skeptic-mathematical identifies. Skeptic-cross-principle's fix is necessary but not sufficient.
  - **Coordination needed**: The headline scoping fix (skeptic-cross-principle) and the registry stability requirement (skeptic-mathematical) are complementary, not competing. Both should be adopted. The synthesis should present them as two components of one fix: scope the headline correctly AND make the implied registry stability requirement explicit.

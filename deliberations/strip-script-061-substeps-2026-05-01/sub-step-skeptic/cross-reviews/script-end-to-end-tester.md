### Dangerous Contradictions

- **Test #9 inverts regression semantics**
  - **script-end-to-end-tester claims**: Rec 2 (P1), test item 9: "Test that `verify_zero_leakage` with `--date 2026-05-01` produces false positives against a document containing prior SIRs (documents the known limitation until Rec 1 is applied)." The framing is that this test documents a known limitation until the fix lands.
  - **sub-step-skeptic claims**: "Closure-driven implementation" section — the entire methodological critique of spec 061 is grounded in Principle IX behavior-over-shape testing: "would removing one real-bug line in the implementation cause at least one test to fail? If not, the test is a tautology." A test that asserts the broken behavior (verify_zero_leakage exits 1 for the correct date) passes when the bug is present and FAILS when Rec 1 (the fix) is applied.
  - **Why this is dangerous**: Implementing test #9 before Rec 1 creates a CI gate that blocks the fix. A developer implementing Rec 1 (excluding HTML comment blocks from the date leakage scan) will see this test go red. The test must then be rewritten or deleted as part of the fix PR. This means the test is not documenting a limitation — it is actively impeding the fix through a false CI failure. The failure mode: a developer sees test #9 red after implementing Rec 1, assumes the fix is incomplete, and reverts or abandons it. The "documentation" test becomes a fix-blocker.
  - **Suggested resolution**: Test #9 should be rewritten as the correct behavior test it becomes post-fix: assert that `verify_zero_leakage` returns an empty list when the date needle appears only inside HTML comment blocks. Alternatively, mark it `@pytest.mark.xfail(reason="blocked on Rec 1 — date leakage check does not exclude HTML comments")` so it is expected to fail now and expected to pass after the fix. Neither approach documents broken behavior as an expected assertion.

  - **script-end-to-end-tester claims**: Rec 7 (P2): "Add a step to the `smoke` job in `evals.yml` that runs: `python scripts/strip-constitution-for-blind.py --input CONSTITUTION.md --output /tmp/CONSTITUTION-blind.md --version v$(...)` and asserts exit code 0." The smoke job currently runs `@pytest.mark.integration` tests on every push — a spec 061 §4.3 taxonomy violation already present in `evals.yml`.

If Rec 7 is implemented without sub-step-skeptic's Rec 2, the smoke job gains a new bash step while continuing to run `TestPersistListShowRoundTrip` (marked `@pytest.mark.integration` in `test_persistence.py`) on every push. The danger is not that the two recommendations conflict logically — they can coexist — but that implementing one without the other creates the appearance of progress while leaving the P1 violation unaddressed. The sub-step-skeptic's Rec 2 is P1; script-end-to-end-tester's Rec 7 is P2. Implementing P2 first violates priority ordering.

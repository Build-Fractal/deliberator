### Final Position Statement

**Non-Negotiables**

1. **The §7 progress header must be corrected before any further spec 061 implementation work is claimed complete.** Without an accurate accounting of what was done out of sequence, which gaps remain P1-open, and which steps have undocumented dependencies, every subsequent contributor acts on a false baseline. The correction is prose-only, costs at most one sentence per step, and is the cheapest single change in the entire recommendation set relative to the orientation value it provides. Treating it as optional because other fixes are more operationally urgent is the exact failure mode — prioritizing velocity over verifiable state — that the contrarian audit was designed to surface. (Sub-step-skeptic Rec 1, surviving.)

2. **The smoke tier pytest invocation must exclude `@pytest.mark.integration`, `@pytest.mark.live`, and `@pytest.mark.eval` tests before the smoke job is augmented with any new steps.** The marker filter is a prerequisite, not a concurrent improvement. Adding bash steps or new CI verification to a structurally violated smoke job compounds undocumented state: a future contributor sees green CI, reads "smoke tier: mock provider, structural validation," and trusts that the integration tests run elsewhere — but they are actually running in smoke on every push. The filter change is two words in one YAML file. There is no cost argument against requiring it first. (Sub-step-skeptic Rec 2, modified.)

3. **Step 11 must have a GitHub tracking issue with SC#3 consequence language before spec 061 is treated as having an accountable completion path.** An untracked deferral of an architectural prerequisite is functionally abandoned regardless of how many other steps are marked DONE. Without the issue, SC#3 is structurally unreachable and the spec cannot close as complete. The tracking issue costs fifteen minutes; the alternative is a spec that cannot close on its own stated success criteria. (Sub-step-skeptic Rec 3, surviving; convergent with spec-061-completeness-auditor New Rec.)

### Systemic Contradictions

- **Self-certification gap in external-verification acceptance criteria**
  - **Manifests in**: GD Disputes 1 and 2 (contrarian prompt absence); the viability of IP's option(a) (retroactive self-documentation); the cycle 2 blind against a post-migration document; the PR #99 self-attestation of "all acceptance criteria satisfied."
  - **Root cause**: Spec 070 §9's acceptance criteria required artifacts (a blind deliberation with an adversarially-configured contrarian agent) that can only be produced by parties conducting an independent process. The closure mechanism — a PR by the implementer — permitted self-attestation to satisfy acceptance criteria that were structurally designed to require external verification. No governance mechanism prevented the implementer from placing the spec in `specs/done/` without producing the required external artifacts.
  - **Implication for spec**: Future specs whose §9 acceptance criteria require external verification (blind deliberations, independent audits) should include a governance mechanism that separates the closure decision from the implementer's self-assessment. One candidate: acceptance criteria referencing blind deliberation artifacts should require a named deliberation directory to exist and its verdict to be PASS before the spec moves to `specs/done/`. Alternatively, the closing PR's merge should be blocked (by review requirement or hook) until the required artifact exists.

- **Two-tier verification structure collapsed into single-track implementation**
  - **Manifests in**: All §6.2/§9.5 discussion; cycle 2 blind against CONSTITUTION-v3.0.0-blind.md; IP's option(a) (retroactive documentation of implementation-PR deliberation as spec-level verification); GD Missed Opportunities #2 and #3 on target substitution.
  - **Root cause**: Spec 070 §6.3 explicitly distinguishes spec-level verification (auditing the §4 conclusions before implementation) from implementation-PR verification (auditing the migrations themselves). This two-tier structure was specified but not enforced; the implementer naturally used their implementation-PR deliberation infrastructure for what should have been a separate spec-level verification track. The implementation-PR deliberations ran against the post-migration documents (testing coherence) rather than against the stripped §4 audit content (testing decision validity) as §6.2 specified.
  - **Implication for spec**: Specs that create two distinct verification tiers should specify in their acceptance criteria that implementation-PR deliberations are not substitutes for spec-level verification, and that the spec-level deliberation must run against the pre-migration document (or stripped spec content), not the post-migration artifact. The target document choice determines which questions the deliberation can answer; this constraint belongs in the spec's §6.2 language.

- **Scope mismatch produces false contradictions in multi-agent cooperative reviews**
  - **Manifests in**: GD's false attribution of AF's §6.2 endorsement; IP's Phase 1 Alignment claiming VI migration completeness (IP scope: governance process) vs. AF's Phase 1 Missed Opportunities identifying §4.1(c) gap (AF scope: content fidelity); IP's Phase 1 endorsing output-conventions structure vs. AF identifying routing error.
  - **Root cause**: The three agents were assigned complementary but not perfectly disjoint scopes (process completeness, content fidelity, governance pragmatics). Each agent optimized within their scope, but when agents reviewed each other, they applied their own scope frame to the other agent's findings — producing apparent contradictions where the agents were simply evaluating different properties of the same artifacts. GD's false attribution occurred because GD conflated GD's own Alignment finding (preset discipline — a process-completeness check) with AF's Alignment section (content-fidelity checks).
  - **Implication for spec**: Multi-agent cooperative closure reviews should explicitly define which agent has primary authority over which finding type, and should include a synthesis brief that maps scope to agent before reviews are filed. This prevents agents from constructing contradictions between findings that address different analytical dimensions.

- **Deferred-item accountability gap in SIR records**
  - **Manifests in**: XIX P3 deferral with explicit "NOT filed as an issue here" in v3.1.1 SIR; Governance list deferred in v3.0.0 SIR without tracking issue; cycle 2B MUST ruling deferred to PR #103 without explicit §4.4 boundary-case documentation; issue #94 unclassified in CONCONV cycle 1 entry.
  - **Root cause**: The SIR format uses P-classification (P1, P2, P3) as a proxy for tracking urgency, but P-classification is only meaningful if paired with a tracking artifact (issue number). When the SIR explicitly states "NOT filed as an issue here," it records the conscious intent to not track — which creates permanent loss risk for the governance record. The SIR has no enforcement mechanism requiring deferred items to land as tracked obligations.
  - **Implication for spec**: The Governance § Removal checklist (and more broadly, the SIR format) should require that any item classified as deferred must either (a) be filed as a tracking issue at ratification time or (b) have a documented exception explaining why it will not be tracked and what recovery path exists if it is ever needed. "NOT filed as an issue here" should be a red-flag phrase that reviewers challenge, not an acceptable deferral mechanism.

- **Verification target selection controls which questions a deliberation can answer**
  - **Manifests in**: Cycle 2 blind against CONSTITUTION-v3.0.0-blind.md (reviewing post-migration coherence rather than migration decision validity); the impossibility of the contrarian argument against a document that already lacks VI and X; IP's option(a) failing to close the gap retroactively.
  - **Root cause**: The spec mandated "agents form independent judgments before seeing the spec's conclusion," but the cycle 2 blind ran against a document that IS the spec's conclusion — the post-migration constitution. The target document selection was a natural choice (verify the implementation is coherent) but it answered the wrong question (was the migration decision correct?). These are complementary but non-equivalent tests; the spec required the latter.
  - **Implication for spec**: Verification deliberations for migration decisions must specify not only the required agent configuration but the required target document — specifically, a document where the migration decision is still unmade. The acceptance criteria for any future migrate-out spec should explicitly state the target document class (pre-decision) for the spec-level blind deliberation, and should prohibit substituting a post-decision document review as a satisfy-equivalent.
